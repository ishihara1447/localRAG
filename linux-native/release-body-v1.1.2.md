OTE-RAG は、社内の文書を読み込ませて日本語で質問できるようにするツールです。
**文書も AI も、すべてサーバーの中だけで動きます。** 外部のクラウドへ文書が
送られることはなく、インターネットに接続していない環境でも動作します。

RHEL 9 + Docker + NVIDIA GPU 向けの、完全オフライン配布物です。

---

## v1.1.1 からの変更

**検索結果を並べ替えるモデル（リランカー）を、中国系でないものへ差し替えました。**

| | v1.1.1 まで | v1.1.2 |
|---|---|---|
| リランカー | `BAAI/bge-reranker-v2-m3`<br>（中国・北京智源人工智能研究院） | **`hotchpotch/japanese-reranker-xsmall-v2`**<br>（日本、MIT） |
| サイズ | 570MB | **37MB** |

新しいモデルの系譜は `cl-nagoya/ruri-v3-pt-30m`（名古屋大学）←
`sbintuitions/modernbert-ja-30m`（SB Intuitions）で、**中国系の混入はありません。**

### 🔴 まずお読みください — 測定した構成は、お届けする構成と同じではありません

以下に精度と速度の測定結果を載せますが、**この測定は開発用の検証構成で行ったもので、
配布物の構成そのものではありません。**

| | 測定に使った構成 | 配布物 |
|---|---|---|
| アプリのイメージ | `1.0.7`（開発用） | **`1.1.0`** |
| チャンク単位の並べ替え | 実装が無く、動いていない | **実装があり、動く** |

配布物では並べ替えモデルの呼び出し回数が増えます。したがって
**下の数値は、お使いの環境でそのまま再現される値ではありません。**
**配布構成での測定は行っていません**（下の「未検証」に記載）。

### 精度（開発用検証構成での測定）

同一条件で交互に各3回ずつ測定し、旧モデル・新モデルとも **27/30** で同点でした。

**ただし「差が無い」ことの証明ではありません。** 30問中、旧と新で答えが分かれたのは
**わずか2問**です。この規模では、仮に差があっても検出する力がほとんどありません。

**合計は同じですが、内訳では増減があります。**

| 設問の種類 | 旧 | 新 |
|---|---|---|
| 定義を説明する | 5/6 | **6/6**（+1） |
| 直接的な事実を問う | 7/8 | **6/8**（−1） |
| 数値を判別する | 5/6 | 5/6（変化なし） |
| 言い換えて問う | 5/5 | 5/5（変化なし） |
| 白書に書かれていないことを問う | 5/5 | 5/5（変化なし） |
| **合計** | **27/30** | **27/30** |

合計が並んだのは、+1 と −1 が相殺した結果です。3回とも1問単位で
完全に同じ結果でした（測定の再現性は確認済み）。

### 速度（開発用検証構成での測定）

並べ替えにかかる時間が **中央値 約4,400ms → 約500ms（約1/9）** に短縮しました。

**回答全体が出始めるまでの時間は測り直していません。** 並べ替えが速くなった分は
短くなるはずですが、配布構成では呼び出し回数が増えるため、具体的な秒数は示せません。

### アップグレードするとき

**旧リランカー（570MB）は `install.sh` が自動で削除します。** 手作業は不要です。

**文書の再取り込みは不要です。** 文書検索に使う `bge-m3` を変更していないためで、
既に取り込んだ文書とベクトルDBはそのまま使えます。

> **`bge-m3`（文書検索）は BAAI 製のまま**です。これを変更すると
> **全文書の再取り込みが必要**になるため、本版では据え置いています。
> 非中国系の要件に対しては未解決の課題として残っています。

## 動作要件

- RHEL 9（x86_64）
- **CPU が AVX2 に対応していること**（🔴 **v1.1.2 で新たに必要になりました**）
- Docker Engine と `docker compose`（v2 以降）。**🔴 podman では動作しません**
  （RHEL 9 は podman が既定のため、`docker` コマンドが podman の別名に
  なっていないか `survey-target.sh` でご確認ください）
- NVIDIA GPU（VRAM 16GB 以上）と `nvidia-container-toolkit`
- 空き容量 40GB 以上（ピーク時 約34GB）

> **🔴 導入前に必ず `survey-target.sh` を実行してください。**
>
> **AVX2**: 新しい並べ替えモデルは AVX2 向けに最適化されています。旧モデルには
> この依存がありませんでした。**対応していない CPU では、エラーにならず
> 静かに遅くなる・精度が落ちる形で問題が出る可能性があります**
> （実際にどうなるかは確認できていません）。
> `survey-target.sh` が対応状況を確認します。
> 非対応だった場合は `survey.txt` をお送りください。対応を検討します。
>
> **nvidia-container-toolkit**: これが無いと GPU があっても使われず、
> 回答に数分かかる状態になります。オフライン環境では後から入れるのが
> 難しいため、事前の確認が有効です。

## 検証済みのこと / 未検証のこと

**本版で検証したこと**

- 新しい並べ替えモデルが実際に読み込まれて動くこと（開発用検証構成のログで確認）
- 同一条件での精度比較（各3回、交互実行）※開発用検証構成
- 配布物に旧モデルが混入していないこと
- **配布物の整合性マニフェストと同梱ファイルが一致すること**（`install.sh` の照合を実行）
- 同梱の手順書の版数が配布物と一致すること
- 7分割の結合が元ファイルと一致すること（本配布物に対して実施）

**v1.1.1 から引き継いでいる検証**（開発環境 WSL2 + Docker + RTX 5070 Ti）

- 配布物の展開から導入、起動、文書の取り込み、出典付き回答、アンインストールまでの通し動作
- GPU が実際に使われること、アンインストールで文書とベクトルDBが残ること

**未検証**

- 🔴 **配布構成（イメージ 1.1.0・チャンク単位の並べ替えが有効）での精度と速度。**
  上記の数値は開発用検証構成での測定です。
- 🔴 **導入先 CPU の AVX2 対応。** `survey-target.sh` でご確認ください。
- 🔴 **AVX2 非対応環境での挙動。** 動かないのか、遅くなるだけなのかを確認していません。
- **RHEL 9 実機での通し実行。** 開発環境が WSL2 のため実施できていません。
  初回導入がその実証を兼ねます。
- SELinux Enforcing 下での動作、systemd による自動起動、firewalld との関係。

**既知の未解決事項**

- コンテナ停止時に強制終了（SIGKILL）となります。実害は確認されていませんが、
  書き込み中の停止では理論上データ破損の余地があります。解消にはコンテナ
  イメージ側の対応が必要です。
- 並べ替えモデルへ渡す文の長さに上限検査が入っていません（モデルの想定は512、
  設定値は8192）。チャンク単位の並べ替えが有効な配布構成では影響が出る
  可能性がありますが、確認できていません。次版で対応します。
