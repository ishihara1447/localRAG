
## 🔴 手順0: 事前調査（最重要・今すぐ実施）

### なぜ最初にやるのか

オフライン環境では、**足りない部品を後から入れるのが極めて困難**です。
特に **nvidia-container-toolkit** は、無いと GPU があってもコンテナから使えず、
**CPU 動作に転落して実用に耐えなくなります**。しかも RPM を依存関係ごと持ち込む必要があります。

「インストールしてみて失敗してから原因を探す」を避けるための手順です。

### 0-1. 調査スクリプトを入手する

導入先はオフラインなので、**ネットの通る端末で取得して持ち込みます**。

**方法A: 直接ダウンロード**

```
https://raw.githubusercontent.com/ishihara1447/localRAG/main/linux-native/survey-target.sh
```

**方法B: リポジトリごと取得**

```bash
git clone https://github.com/ishihara1447/localRAG.git
# linux-native/survey-target.sh を取り出す
```

**方法C: 画面越しにコピーして貼り付ける**

シェルスクリプト1ファイルで**外部依存が一切ありません**。
ファイル転送手段が限られる環境では、これが最も確実です。

### 0-2. 実行する

```bash
bash survey-target.sh > survey.txt
cat survey.txt
```

- **root 権限は不要**です
- **読み取りのみ**で、インストールも設定変更もパッケージ導入も**一切行いません**
- 一部の項目は `sudo` があるとより正確に取れますが、無くても動きます

### 0-3. 結果を開発側へ渡す

`survey.txt` の**全文**をそのまま渡してください。

### 0-4. 結果の読み方（何が問題になるか）

調査スクリプトは以下を確認します。**`[NG]` が出た項目は導入前に解決が必要です。**

| 項目 | `[NG]` だったときに起きること |
|---|---|
| **nvidia-container-toolkit なし** | **GPU があってもコンテナから使えない。**CPU 動作になり、回答に数分かかって実用外になる。**RPM を依存関係ごと持ち込む作業が別途必要** |
| **nvidia-smi なし** | GPU ドライバが未導入。ホスト側の作業が必要 |
| **docker コマンドが podman の別名** | 本配布物は使用できません（`[NG]` として報告されます）。**開発元で podman 向けの制御スクリプトを用意します。モデルやイメージを含む 12GB の本体は共通のため、作り直しにはなりません** |
| **compose なし** | 現行構成では起動できない |
| **docker デーモンへ到達できない** | デーモン未起動か権限不足。`docker` グループへの追加、または `sudo` での実行が必要 |
| **x86_64 でない** | 配布物は x86_64 前提。**作り直しが必要** |
| 🔴 **CPU が AVX2 非対応**（v1.1.2 で新規） | 検索結果を並べ替えるモデルが AVX2 向けに最適化されているため、想定どおり動かない可能性がある。**エラーにならず、静かに遅くなる・精度が落ちる形で出る可能性がある**（実際にどうなるかは未検証）。該当した場合は `survey.txt` を保守担当へ送付のこと |
| **ディスク不足** | 導入できない。約 34GB のピーク使用量が必要 |
| **ポート 3001 / 11434 が使用中** | 競合するので、ポート変更または既存プロセスの停止が必要 |

`[注意]` が出る項目のうち、**SELinux が Enforcing** は問題ありません。
**配布する compose ファイル側で対応済み**です（バインドマウントに `:z` ラベルを付けています）。
環境側の設定変更は不要です。

## 手順1: 資材の受け取り

配布物は 11.9GiB（12,794,844,414 バイト）あり、GitHub Release の1ファイル上限（2GB）を超えるため**分割**されます。
Windows 版と同じ方式です。

ネットの通る端末で全ファイルを取得し、**同じディレクトリ**に置いてください。

```bash
gh release download linux-v1.1.2 --repo ishihara1447/localRAG --dir ~/ote-rag-install
```

取得するもの:

| ファイル | 用途 |
|---|---|
| `ote-rag-linux-x64-v1.1.2.tar.gz.001` 〜 `.007`（7分割） | 本体（分割） |
| `MANIFEST.txt` | SHA-256（破損チェック用） |
| `join.sh` | 結合ツール |
| `survey-target.sh` | 手順0の調査スクリプト（**資材にも同梱されます**） |

### 1-1. 結合する

```bash
cd ~/ote-rag-install
cat ote-rag-linux-x64-v1.1.2.tar.gz.[0-9][0-9][0-9] > ote-rag-linux-x64-v1.1.2.tar.gz
```

または同梱の `join.sh` を実行してください（**SHA-256 検証まで自動で行います**）。

```bash
bash join.sh
```

> 10GB を超えるダウンロードは途中で壊れることがあります。**`join.sh` を推奨します。**

## 手順2: 完全性の検証

**展開する前に必ず確認してください。** 壊れたまま進めると、原因の分かりにくい失敗になります。

```bash
sha256sum -c MANIFEST.txt
```

`OK` 以外が出た場合は、**そのパートだけ再取得**してください（分割方式の利点です）。

検証できたら展開します。

```bash
tar xzf ote-rag-linux-x64-v1.1.2.tar.gz
cd ote-rag-linux-x64-v1.1.2
ls
```

## 手順3: インストール

### 3-1. 実行する

```bash
sudo ./install.sh
```

**root 権限が必要**です。インストーラは以下を順に行います。

| # | 内容 |
|---|---|
| 1 | **前提条件の確認**（ここで足りないものがあれば、進まずに日本語で停止します） |
| 2 | 配布物の完全性を検証（SHA-256） |
| 3 | Docker イメージを読み込み（**オフラインで完結**） |
| 4 | **コンテナから GPU が見えることを確認** |
| 5 | プログラムを配置 |
| 6 | モデルとデータ領域を準備（**約11GB のコピー。数分かかります**） |
| 7 | 自動起動（systemd）を設定 |
| 8 | サービスを起動 |
| 9 | 起動を待機（**最大5分。初回はモデル読み込みに時間がかかります**） |

**インターネットへは一切アクセスしません。** `docker pull` / `ollama pull` / `dnf install` / `curl` による外部取得は含まれていません。

**何度実行しても壊れません（冪等）。** 既存の文書データ（`documents` / `lancedb` / `*.db`）は上書きされません。

### 3-2. よく使うオプション

```bash
sudo ./install.sh --help          # オプション一覧
```

| オプション | 用途 |
|---|---|
| `--data-dir /var/lib/ote-rag` | **モデルとデータの配置先を変える**。約11GB使うので、`/opt` の容量が足りない場合に指定 |
| `--port 8080` | Web UI のポートを変える（既定 3001） |
| `--bind 0.0.0.0` | **LAN の他の端末からも使う場合のみ**。既定は `127.0.0.1`（同一端末のみ） |
| `--no-systemd` | 自動起動を登録しない |
| `--no-start` | インストール後に起動しない |

> 🔴 **`--bind 0.0.0.0` を使う場合の注意**
> 既定では同一端末からしか接続できません。LAN に公開する場合、
> **必ず先に Web UI で管理者パスワードを設定してください。**
> 設定前に公開すると、LAN 内の誰でも文書を閲覧できる状態になります。

### 3-3. 前提条件で止まった場合

インストーラは**足りないものを日本語で具体的に表示して停止**します。黙って進めることはありません。

より詳しい状況は、同梱の調査スクリプトで確認できます。

```bash
bash survey-target.sh
```

## 手順4: 動作確認

### 4-1. サービスの状態

```bash
systemctl status ote-rag
docker ps
```

`ote-rag-app` と `ote-rag-ollama` の2つのコンテナが動いていれば正常です。

### 4-2. Web UI を開く

```
http://127.0.0.1:3001
```

**初回は管理者アカウントの作成画面**が出ます。**必ずパスワードを設定してください。**

### 4-3. GPU が使われているか確認する ★重要

**ここは必ず確認してください。** GPU が使われていないと、回答に数分かかり実用になりません。

```bash
nvidia-smi
```

質問を1回投げた直後に実行し、**`ollama` のプロセスが GPU メモリを使っていれば正常**です（コンテナ名は `ote-rag-ollama`、プロセス名は `ollama`）。
GPU メモリの使用が 0 のままなら、CPU 動作に転落しています（`nvidia-container-toolkit` を確認）。

### 4-4. 実際に質問してみる

1. ワークスペースを作成
2. PDF を1つアップロード
3. その内容について質問する

**回答が数秒〜十数秒で返れば正常**です。数分かかる場合は GPU が使われていません。

## RHEL 9 特有の注意点

### SELinux（対応済み・作業不要）

RHEL 9 は既定で **Enforcing** です。この状態でバインドマウントに適切なラベルが無いと、
**コンテナがモデルファイルを読めず `Permission denied` で起動に失敗**します。

**配布する compose ファイル側で `:z` ラベルを付けて対応済み**なので、環境側の変更は不要です。
SELinux を無効化する必要はありません（**無効化しないでください**）。

### podman ではなく Docker が必要

RHEL 9 は **podman が既定**で、`podman-docker` パッケージが入っていると
`docker` コマンドが podman の別名になります。

手順0の調査スクリプトがこれを `[NG]` として検出します。**podman だった場合は開発元へご連絡ください。**

異なるのは compose の書式・GPU の渡し方・SELinux ラベルの扱いで、影響を受けるのは制御スクリプトと compose ファイル（合計 1,200 行程度）です。**Docker イメージ・モデル・リランカーを含む 12GB の本体はコンテナランタイムに依存しないため、搬入し直す必要はありません。**

### cgroup v2

RHEL 9 は cgroup v2 です。Docker 20.10 以降なら問題ありません。調査スクリプトが確認します。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| **回答が数分かかる** | **GPU が使われていない。**`nvidia-smi` で確認。`nvidia-container-toolkit` の導入状況を確認する |
| **`Permission denied` で起動失敗** | SELinux のラベル。配布物の compose を使っているか確認（自作の compose に差し替えていないか） |
| **ポート 3001 に繋がらない** | `--bind` の既定は `127.0.0.1`。**別端末からは接続できない**。同一端末で確認するか `--bind 0.0.0.0` で入れ直す |
| **`docker: command not found`** | Docker 未導入、または podman のみ。手順0の調査結果を確認 |
| **ディスク不足で失敗** | `--data-dir` で容量に余裕のある場所を指定して再実行 |
| **起動待ちがタイムアウト** | 初回はモデル読み込みに時間がかかる。`docker logs ote-rag-app` でログを確認 |

ログの確認:

```bash
docker logs ote-rag-app --tail 100
docker logs ote-rag-ollama --tail 100
journalctl -u ote-rag -n 100
```

## この製品について

**取り込んだ文書は一切外部へ送信しません。** LLM・埋め込み・リランカー・OCR をすべて同梱しており、
**インターネットに接続していない環境で完全に動作します**。

外部へ出る経路は、2026-07-28 に通信をフックした実測で **0件** であることを確認しています
（詳細は `docs/OFFLINE_INSTALL_HARDENING_2026-07-28.md`）。

**同梱していない言語の OCR はできません**（日本語・英語のみ）。
不足分を外部から自動取得することは、意図的に無効化しています。
