# hakusho-eval 失敗4問 根本原因分析（2026-07-18）

対象: OTE-RAG（AnythingLLM fork）hakusho-eval 30問中の失敗4問（26/30時点）。
分析方法: コード変更なし。稼働中コンテナ `anythingllm` 内で `performSimilaritySearch` を直接実行し（workspace `5ec7ec63-…`, bge-m3, hybrid ON, topN=8, threshold=0.25, cushion ON/OFF・rerank ON/OFF比較）、原文 `R07zenpen.pdf-559eabd8….json` の pageContent と突き合わせた。チャットAPIは使用していない。

原因分類の凡例:
- (A) retrieval失敗（正解チャンクがtop8に入らない）
- (B) cushion/rerankで正解が落ちる
- (C) 生成失敗（正解がコンテキストにあるのにLLMが誤答・拒否）
- (D) 曖昧性（複数の類似記述から誤選択）
- (E) 評価セット問題

## Q1. 三文書の閣議決定日 → 「情報がありません」（拒否）

- 期待: `(令和4年|2022年)12月16日`（hakusho-eval.py L40）
- 原文確認: **実在**。pos 334055付近に脚注形式で3回:
  「5国家安全保障戦略について（**令和4年12月16日**国家安全保障会議及び閣議決定）6国家防衛戦略について（同）7防衛力整備計画について（同）」。
  ※「三文書」という語と「12月16日」が同一文で結ばれた記述は本文には無い（本文は「2022年に策定された」止まり）。
- retrieval実行（元クエリ, cushion ON, rerank:false）: **正解チャンクはtop8の#1（score 0.585）に存在**。cushion後テキストにも脚注3行が完全に残存していることを全文出力で確認。
- 分類: **(C) 生成失敗**。正解はLLMに渡っている。誤答の機構（推定）:
  1. 日付が「脚注」形式で、質問語「三文書」「閣議で決定」と表層が離れている（脚注は「国家安全保障会議及び閣議決定」）
  2. 同時に渡る#2チャンクが「2022年に策定された国家安全保障戦略、国家防衛戦略、防衛力整備計画」と月日なしで述べており、gemma4:12bが「正確な日付は不明」と安全側に倒れた可能性
- 対策案:
  - **プロンプト層（推奨・低リスク）**: システムプロンプトに「脚注・括弧内の日付（○年○月○日△△決定）も回答根拠として扱う」「部分的な日付情報でも文書内にあれば提示する」を追加。効果見込み中〜高、副作用ほぼ無し
  - 生成層: gemma4:12bの限界の可能性もあるため、この問のみ複数回サンプリングで再現率を測ると切り分けが完全になる（今回未実施＝未確認）

## Q2. 2025年度防衛関係費の歳出額（防衛力整備計画対象経費） → 誤: 87,005億円

- 期待: `8兆4,748億|84,748億`（L45）
- 原文確認: **両数値が実在し近接**。
  - 正解: pos 365624「歳出ベースは…**防衛力整備計画対象経費として8兆4,748億円**（対前年度比7,498億円（9.7％）増）」
  - 罠: pos 366417 図表注記「（注）１…SACO関係経費と米軍再編関係経費…**これらを含めた防衛関係費の総額は、歳出額については…令和7（2025）年度は87,005億円**」
- retrieval実行（元クエリ, cushion ON, rerank:false）: **正解チャンクは#4かつ最高スコア0.797**で「防衛力整備計画対象経費として8兆4,748億円」を含む。一方**#0に罠チャンク**（87,005億の注記）が入り、しかも罠側だけが質問の字面「**歳出額**」をそのまま含む（正解側は「歳出ベース」）。
- 分類: **(D) 曖昧性（＋生成の選択ミス C）**。retrievalは成功。LLMが「歳出額」の字面一致と「総額」という語に引かれ、SACO込み総額を選択した。質問の限定句「防衛力整備計画対象経費」を制約として使えていない。
- 対策案:
  - **プロンプト層（推奨）**: 「質問に括弧書き・限定句がある場合、その語句を含む記述を優先する」「複数の類似数値がある場合は各数値の定義（何を含む/含まないか）を確認して選ぶ」を追加。効果見込み中、副作用小
  - 生成層: 回答時に「採用した数値の定義」を一言添えさせる（self-check）。トークン増の副作用あり
  - 評価層: この問は12Bモデルには難問側。誤答が続くなら「SACO込み総額との違いに注意」等はリークになるため入れない方針を維持しつつ、部分点設計を検討

## Q3. 個室化の整備完了目標年度（陸 vs 海・空） → 「情報がありません」（拒否）

- 期待: 2025年度と2028年度の両方（L49）
- 原文確認: **実在するが文書中1箇所のみ**（pos 20068, 巻頭特集2のダイジェスト面）:
  「営内隊舎の居室の個室化 プライバシーに配慮し、**陸上自衛隊は2025年度、海上・航空自衛隊は2028年度に整備完了**を目指して、間仕切りなどによる個室化を推進」
- retrieval実行で判明した決定的事実: **この1文がチャンク境界で分断されている**。
  - 後半チャンク（「**衛隊は2028年度**に整備完了を目指して…」— 「海上・航空自｜衛隊」の語中で切断）は元クエリで**#0/score 0.651に入る**（cushion OFFの生チャンクでも先頭が「衛隊は2028年度…」であることを確認＝cushionの切除ではなくチャンク境界そのもの）
  - 前半チャンク（「…（指定場所生活調整金）…陸上自衛隊は2025年度、海上・航空自」で終わる。主内容は手当・給付金の羅列）は:
    - 元クエリ topN=25 で**14位**（hybridのFTS枝でヒット、denseスコアなし）
    - **rerank:true でもtop8圏外**（rerankerもチャンク主部が手当の話のため上げない）
    - 言い換えクエリ2種（「隊舎居室の個室化はいつまでに完了する予定ですか」「個室化の整備完了時期 陸上自衛隊 海上自衛隊 航空自衛隊 プライバシー」）でも**top8圏外**
  - つまりLLMには「（主語欠損の）衛隊は2028年度に整備完了」しか渡らず、「陸自と海・空自それぞれ」を問う質問に答えられず拒否。拒否はむしろ誠実な挙動
- 分類: **(A) retrieval失敗**。ただし根本はチャンク層: TextSplitterのデフォルト（chunkSize=1000, overlap=20文字, DB上のカスタム設定なし）で回答文が語中分断され、前半が「内容の異なるチャンクの末尾」に取り残された構造問題。どんなクエリ・rerankでも救えないことを確認済み
- 対策案:
  - **チャンク層（根本対策）**: chunkOverlapを100〜200文字に増やして再取り込み（1748チャンクの再embedが必要）。効果見込み高。副作用: 再取り込みコスト、チャンク数増
  - 検索層（代替）: 隣接チャンク展開（ヒットチャンクの前後チャンクを自動添付）。cushionが後段でノイズを絞る前提なら相性が良い。実装コスト中
  - 文分割層: 日本語文境界（。）優先のセパレータ設定も緩和策になるが、白書のような箇条書き主体レイアウトでは効果限定

## Q4. 陸・海・空自を一元指揮する新司令部の「発足」時期 → 誤: 2006年3月

- 期待: `2025年3月24日|令和7年3月24日`（L62）
- 原文確認: **実在**（複数箇所）。pos 388147「2025年3月24日、市ヶ谷に統合作戦司令部を新設しました」ほか、巻頭特集1にも同旨。
  誤答側も実在: pos 387795 の**解説コラム見出し「統合作戦司令部の新設」の直後に「2006年3月、統幕の新設…」**（統合幕僚監部の話）が続く。PDFテキスト抽出でコラム見出しと本文が結合した箇所
- retrieval実行（元クエリ, cushion ON, rerank:false）: 8件中、
  - **#3（0.623）に正解**「2025年3月24日、市ヶ谷に統合作戦司令部を新設しました」、#4（0.630）にも「2025年3月に…統合作戦司令部を市ヶ谷に設置した」
  - **#1（0.615）に罠**: cushion後テキストで「**統合作戦司令部の新設 2006年3月、統幕の新設**、陸・海・空幕から統幕への運用機能の移管…」— 見出し結合により「統合作戦司令部の新設＝2006年3月」と読める偽装文になっており、正解より上位に提示される
- 分類: **(D) 曖昧性（文書抽出起因）＋生成の選択ミス**。retrievalは成功。原因の芯はPDF抽出時の見出し・本文結合が作った偽装文で、LLMは「新設」という語の一致（質問は「発足」）と提示順の早さから2006年3月を選んだと推定。なお同チャンク内に「両者は趣旨や位置づけが異なる組織」という手掛かりはあったが活用されなかった
- 対策案:
  - **プロンプト層（推奨）**: 「複数の年月が候補になる場合、それぞれの年月が何の出来事かを主語まで確認して選ぶ」を追加。効果見込み中
  - 文書層（根本）: PDF抽出時のコラム/見出しマーカー処理の改善、または該当箇所のみテキスト修正して再取り込み。効果確実だが個別対応的
  - cushion層: 文分割が見出し結合文をそのまま1文として残すため、「見出し様の短い名詞句＋日付」で始まる文への減点等は考えられるが、過剰工学のリスクあり（非推奨）

## 横断考察

1. **retrievalは4問中3問で成功している**（Q1, Q2, Q4は正解チャンクがtop8内、うちQ2は最高スコア）。cushionが正解文を落とした例も無かった（(B)該当ゼロ）。現構成（bge-m3 + hybrid + cushion）の検索品質は高く、残る失敗の主戦場は**生成側の「複数候補からの選択」**にある。
2. **失敗3問（Q1/Q2/Q4）の共通パターンは「正解と紛らわしい記述の同時提示」**:
   - Q2: 定義の異なる類似数値（84,748 vs 87,005）
   - Q4: 見出し結合による偽装文（2025/3/24 vs 2006/3）
   - Q1: 月日なしの併記文（「2022年に策定」）が拒否を誘発
   gemma4:12bは質問内の限定句（「防衛力整備計画対象経費」「発足」「三文書」）を候補の絞り込みに使えていない。**「候補が複数あるときは質問の限定句と各候補の定義・主語を照合してから選ぶ」旨のシステムプロンプト追記が、コード変更なしで3問に同時に効く最有力の一手**。
3. **Q3だけは純粋な構造問題**（チャンク境界による回答文の語中分断＋前半チャンクの内容ミスマッチ）。プロンプトでは救えず、**chunkOverlap増強（再取り込み）か隣接チャンク展開**が必要。1文にしか正解が無い設問はこの種の分断に対して脆弱で、評価セット側の頑健性（複数箇所に記述がある事実を問う）という観点でも留意。
4. PDF抽出品質（脚注形式Q1・見出し結合Q4・ダイジェスト面の表組みQ3）が3問に関与しており、白書のような複雑レイアウト文書では**抽出後テキストの構造（見出し/脚注/表）の保全**が次の改善テーマ。

- rerank比較はQ3のみ実施（Q1/Q2/Q4はrerank:falseで既に正解がtop8内のため不要と判断）。
