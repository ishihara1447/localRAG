# 調査: 「検索は改善したのに回答が改善しない」— retrieval-generation gap

調査日: 2026-07-28 / 担当: Claude Code（調査担当）／英語圏一次情報を優先
位置づけ: 残り約19人日の投資先を決めるための、実装前の先行研究確認（文献先行の原則）

## サマリー

1. **この現象は2024〜2026年に名前が付き、独立に複数回再現された既知の失敗モード。** 我々の観測は異常ではない。IR指標とRAG回答品質の相関が弱いことは **SIGIR 2024 (eRAG)** が定量済み。
2. **しかし「だから生成側に投資せよ」は時期尚早。** 我々の構成（1,229トークン枠＋文抽出クッション）では、**`anchor_coverage@8` は生成器が実際に読む文脈を測っていない**。**測定対象の付け替え（クッション通過後のカバー率）が最優先。**
3. 反証も明確。**BERGEN (EMNLP Findings 2024) は「検索品質が上がればLLM性能はlarge marginで上がる」を大規模に実証。** 伝達するのは「低recall域」「文脈がそのまま生成器に渡る」「生成器が十分大きい」条件下。**我々は3条件のうち2つを外している。**

## 1. 呼称と実証

**標準的呼称は未確立。** 最も直截なのが Mathur et al. (2026) **"Retrieval Improvements Do Not Guarantee Better Answers"**（arXiv:2603.24580）。結論は「domain-specific fine-tuning は検索指標を改善するが end-to-end QA を一貫して改善しない」。さらに「**検索が強くなると、コーパスに正解が無いときにかえって自信満々のハルシネーションが増える**」。※**効果量は本文から抽出できず未確認**。

より定量的な一次情報:

- **Salemi & Zamani, SIGIR 2024（arXiv:2404.13781）**: **「query-document relevance ラベルに基づく検索評価は、RAGの下流性能との相関が小さい」**を実証し eRAG を提案。**査読付き**
- **Trappolini et al.（arXiv:2510.21440）**: nDCG/MAP/MRR は関連文書を後方に動かすと単調減少するが、**LLM精度はU字で単調でない**。強い distractor と弱い distractor を入れ替えると**6モデルで精度差最大9ポイント**なのに**従来指標は同一スコアと判定**する。提案指標 UDCG は RAG精度との相関を **nDCG比+36%** 改善

**「検索+X% → 生成+Y%」の変換係数を明示した論文は発見できなかった。**

## 2. 原因ごとの実証

### 2-1. Lost in the Middle（実証強、ただし我々には効きにくい）
Liu et al.（arXiv:2307.03172）、Found in the Middle（arXiv:2406.16008）が**内容非依存のU字型 attention bias** を attention 行列に帰着。
→ **我々の文脈は最大1,229トークン。この規模ではU字は極めて弱い。主因ではない（推測）。**

### 2-2. 順位が変わっても生成が上位しか読まない（条件付き実証）
**Long-Context LLMs Meet RAG, ICLR 2025（arXiv:2410.05983）**。Gemma-2-9B / Mistral-NeMo-12B。**passage順の並べ替えの効果は「取得数が小さいときは negligible」、多いときのみ有意**。また**強い検索器ほど hard negative が有害**で性能は**逆U字**。
→ **topN=8＋文20本という小さい枠では、順序改善の寄与はほぼ無いと予測される。「リランカーを直したのに回答が変わらない」の最有力の一般説明。**

### 2-3. 過剰拒否（実証あり）
**RefusalBench**（Microsoft Research, arXiv:2510.10390）: 30以上のモデルで「危険な過信か過剰な慎重さのどちらかに系統的に振れる」。重要なのは「**refusal は detection と categorization の分離可能な2能力からなり、スケールも長い推論も改善しない**」。
→ **プロンプト改善2回が両方とも過剰拒否を悪化させた我々の実測と整合。「プロンプトで拒否閾値は制御できない」は文献側でも支持される。**

### 2-4. 🔴 文脈圧縮・文抽出での情報損失（本件で最重要）
- RECOMP系（AttnComp, arXiv:2509.17486 等）: **明示的圧縮は over-removal による compression loss を持ち、質問を考慮しない手法は key information を落としやすい**
- **InfoGain-RAG**（arXiv:2509.12765）: **「関連度が高くても冗長な文書はある」**を出発点に、**関連度ベースの並べ替えは回答品質の意味ある改善に繋がらない**と明示。生成confidenceの差分で並べ替えると NaturalQA EM で **naive RAG比 +17.9%、既存ランキング型RAG比 +12.5%**、GPT-4o上で平均 **+15.3%**

> **🔴 これが我々の「@8=1.00 なのに要素カバー率が低い」の最有力機構。** クッションは cross-encoder の**関連度**で上位約20文を選ぶ。多要素質問では**要素①に強く一致する文が20本の枠を占め、要素②③④の文が枠外に落ちる**。**関連度最大化と要素網羅は別目的**であり、InfoGain-RAG の指摘そのもの。**推測だが検証は安価。**

## 3. oracle 実験は標準手法か → **完全に標準**

Oracle-RAG（検索器を gold passage 供給に置き換え生成の上限を測る）は現行RAG研究の定型的 ablation。
- **BERGEN**（arXiv:2407.01102, EMNLP Findings 2024）が oracle passage を標準条件として掲載
- **arXiv:2506.20051** が oracle retrieval context を**経験的上限**として明示使用
- **arXiv:2601.19827** が Gold-Context を3つの評価レジームの1つとして11モデルに適用

**分解の作法は4段が定石**: retrieval recall ／ context precision・utility ／ faithfulness ／ answer relevance・completeness。**Sufficient Context** はここに「**文脈は十分だったか**」という第5軸を追加。

---

## 4. 小型モデル特有の問題（該当。ただし1本は要注意）

- **Sufficient Context, ICLR 2025（arXiv:2411.06037）**: **大型モデルは文脈が十分なら正答するが不十分でも棄権せず誤答。一方、小型モデル（Llama 3.1 / Mistral 3 / Gemma 2）は「文脈が十分でもハルシネーションまたは棄権する」**。Google公式ブログでは Gemma が「文脈なし誤答10.2% → 不十分文脈で誤答66.1%」
  → **`gemma4:12b` は Gemma 2 の後継。「証拠があるのに使えない／棄権する」が系統として報告されているファミリー本人であり、本件と直撃。査読付き（ICLR2025）**
- **A Reality Check on Context Utilisation（arXiv:2412.17031）**: **文脈関連度指標は回答品質を予測しない**、oracle文脈でも期待される伸びに届かない
- ⚠️ **Can Small LMs Use What They Retrieve?（arXiv:2603.11513）**: 「oracle検索でも7B以下は85〜100%の割合で正解を抽出できない」と報告。**ただし単著プレプリント・査読なし・8Bまで。数値が他文献（Llama-3.1-8B が gold文脈で EM 60%超）と整合せず、採点がEM厳格である等の artifact の疑いが強い。方向性は他論文と一致するが、数値は引用に耐えない**

**gemma4:12b 規模ちょうどの実測は発見できなかった。** 12BはSufficient Contextの「小型」側とBERGENの「使える」側の境界領域で、**文献からは結論できない。我々の oracle 実験でしか分からない。**

## 5. 生成側の改善手法（プロンプト以外）

| 手法 | 報告効果 | 出典 | オフライン12Bで可能か |
|---|---|---|---|
| **情報利得ベースの文選択**（関連度でなく「入れると正答confidenceが上がるか」） | NaturalQA EM **naive比+17.9% / 既存ランキング型比+12.5%** | InfoGain-RAG | **概念は可**（logprob差で近似。推論回数が文数ぶん増える） |
| top-k を減らす／文脈を絞る | 強い検索器では逆U字 | ICLR2025 | **我々は既に強く絞っており、方向は逆かもしれない** |
| retrieval reordering | **少数passageでは negligible** | 同上 | **本件では効果薄と予測** |
| sufficient-context判定＋選択的棄権 | 応答時正答率 **+2〜10%** | ICLR2025 | 可能。**ただし要素カバー率は上がらない** |
| リランカー導入 | NQ Match 0.637→0.658 | BERGEN | **既に実施済み** |
| 評価指標を UDCG に置換 | 相関 **nDCG比+36%** | arXiv:2510.21440 | 可能（訓練不要） |

## 6. 🔴 反証 — どういう条件なら伝わるのか

1. **BERGEN（EMNLP Findings 2024）**: 20+検索器・20+LLMの統制比較で **「with increased retrieval quality, LLM performance improves across LLMs by a large margin」**。**同時に反例も報告**: TruthfulQA・ELI5 では**文脈追加で生成性能が悪化**。→ **タスク依存**
2. **🔴 Powerless Noise（SIGIR 2026, arXiv:2607.03615）**: 「ランダム文書を混ぜると最大約35%精度が上がる」を再現検証。**元設定（4bit量子化・chat template無し・生成15トークン上限・NO-RESオプション付き）では再現するが、instruction template採用・NO-RES削除・生成上限100トークンに緩めると効果は消滅**。結論は「**観測された効果はプロンプト定式化・デコード制約・評価方法の相互作用に由来する**」
   → **本件に対する最も重い警告。「RAGの奇妙な観測」の多くは、生成長制限・拒否オプション・採点方式の artifact だった。我々も 1,229トークン枠・強い拒否指示・要素マッチ採点という、この論文が artifact 源と名指しした条件を全部備えている**

### 繋がる条件／繋がらない条件

| 繋がりやすい | 繋がりにくい |
|---|---|
| recall が低い域からの改善 | 既に高い域での改善（**逆U字の頂点付近**） |
| 単一事実（single-hop）質問 | **多事実・集約質問** |
| 検索結果が**そのまま**生成器に入る | **圧縮・要約・文抽出が間に入る** |
| 生成器が十分大きい | **小型モデル** |
| 生成長・出力形式に余裕がある | **生成長制限・拒否オプション付き** |
| distractor が弱い | **強い検索器が生む hard negative** |

> **我々は右列に5つ該当している。「繋がらないのが当然の条件」を自作している可能性が高い。**

## 7. 日本語特有の論点

**査読付き一次情報は発見できなかった。**
- NVIDIA技術ブログ（**ベンダー主張・査読なし**）: JMTEBでリランカー追加により **nDCG@10 が3.7pt改善**。**end-to-endの回答品質は体系的に測っていない**
- 国内技術ブログ群（**すべて査読なし**）: 「誤答の原因が検索・解釈・選別・生成のどこか切り分けられない」が共通の困りごと
- **日本語で retrieval-generation gap を定量した公開データは存在しない**

→ **日本語×多要素×行政文書での実測は、我々が作れば公開データとして希少性がある**

## 8. 🔴 測定の妥当性への懸念

1. **`anchor_coverage@8` は生成器の入力を測っていない。** パイプラインは 8チャンク→クッション→約20文→1,229トークン枠。**日本語20文（1文40〜60字）は約800〜1,200トークンで実効枠のほぼ全量**。**「chunk@8 に入った」と「生成器が読んだ」の間に非可逆な情報損失段が挟まっている。24%の検索改善が伝わらないのは当然でありうる**
2. ~~McNemar p=1.0 と純増+4 が整合しない~~ → **【Claude本体が検証・却下】** 46→50 は2つの別々の比較（46→49が索引フィルタ修正、49→50がリランク）の混同。**リランクは純増+1で、b=3・c=2 なら p=1.0 は正常に成立する**（実際に計算して確認）
3. **検出力が構造的に足りない**（Webber et al., CIKM 2008）。**Claude本体が独立に再計算**:

| 検出したい差 | 必要な不一致ペア | 必要要素数 | 設問数 |
|---|---|---|---|
| **5pt** | 123 | **616** | **154問** |
| 8pt | 47 | 233 | 58問 |
| 10pt | 29 | 145 | 36問 |

**現状の79要素/19問では、真に+5ptの改善があっても大半の場合に見逃す。**「差が誤差範囲」は「効果がない」ではない。

### (a)(b)(c) の判断

- **(b) 測定側を先に直す — 明確に最優先。** #1・#2・#3 で計6.5〜13人日。**現状は「効果がない」と「検出できていない」を区別できず、いま生成側に投資しても成否を判定できない**

- **(a) 生成側への投資は保留。** #2 の oracle 上限が出るまで判断材料がない。**gemma4:12b 規模の実測は文献に存在せず、文献では決められない**

## 不明点

1. 「検索+X% → 生成+Y%」の変換係数を実測した研究は**発見できなかった**
2. **gemma4:12b（Gemma 3/4系）の context utilization の第三者実測が無い**
3. arXiv:2603.24580 の効果量が本文から抽出できず**未確認**
4. arXiv:2603.11513 の数値は**他文献と整合せず引用に耐えない**
5. **日本語での retrieval-generation gap の定量データは国内外とも存在しない**
6. **文抽出クッションと同型の機構での要素網羅率への影響の実証は発見できず。#1・#4 は先行事例のない領域**
