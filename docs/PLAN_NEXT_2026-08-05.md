## 1. 優先順位の考え方

**原則4「測れないものは直さない／測定基盤は改修より先」に従う。**

いま最大の障害は **A（捏造を測れない）** である。これが直らない限り、
精度向上のどの施策も「改善したのか、忠実性を売り払ったのか」を判別できない。
実際、今日それで誤った結論を出しかけた。

D（切り詰め）は設計欠陥だが、**現行設定では発火していない**ことを実測で確認した
（コンテナログの切り詰め痕跡 0件）。したがって**いま直す必要はなく**、
文脈を増やす施策に着手する前提条件として扱う。

## 2. 作業計画

### ステップ1 — `[X]` 判定を信頼できるようにする ★最優先

**これが無いと精度向上の効果を判定できない。**

| # | 作業 | 所要 |

| 1-2 | **判定方式の決定**: (a) 正規表現を個別修正 (b) LLM-as-judge へ移行 (c) 両者の併用 | 0.5日 |

| 1-5 | 保存済み回答（TOPK=8/24 の166問）を再採点し、**真の捏造件数を確定** | 1時間 |

**完了の定義**: 既知の誤検出10件が誤検出と判定されず、既知の真の捏造（Q158・Q139・Q17）が検出される。

> 🔴 **判定方式の選択で注意**: LLM-as-judge は揺れが入る。
> 決定的判定を残しつつ judge を併用し、**両者が食い違った件だけ人手確認**する形が現実的。
> 申し送り（`d04_q06_same_pathology`）も「[X] の judge 移行とまとめて直す」としている。

### ステップ2 — 出荷中の捏造1件（Q158）を潰す

**現行製品の既知欠陥。** 「2025年度の概算要求額」を問われ、白書に無いのに
当初予算の数値を答える。ステップ1完了後、**再現→原因特定→対処**の順で。

ステップ1が終われば、同種が他にどれだけあるかを機械的に数えられる。

## 3. 順序の根拠

```
[1] [X]判定を直す ──► [2] 出荷中の捏造を潰す ──► [3] 精度向上に再挑戦
                                                      ▲
[4] 製品系統の整理（独立して進行可）───────────────────┘
```

**1 を飛ばして 3 に行かない。** 今日それをやって、捏造3倍の変更を
「精度が上がった」と報告しかけた。

**4 は 1〜3 と独立**なので、待ち時間に進められる。4-3 はユーザー作業なので早めに依頼する。
