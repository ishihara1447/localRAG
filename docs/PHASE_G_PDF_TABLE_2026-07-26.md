## 0. 結論（先に書く）

### 判断: **PDFの表構造対応（座標再構成）は実装しない。**

理由は3つで、いずれも実測に基づく。

1. **前提が事実と違った。** Q12・Q15 の gold ページは**表ではない**。Q12 の主ページ（phys 232）は**ドーナツ円グラフ2枚**、Q15（phys 23–24）は**雑誌型の年表インフォグラフィック**である。**Phase G が想定する「表」は、この2問には1つも関与していない。**
2. **本文書に実在する「本物の表」は、現行の抽出で既に行×列が正しく取れている**（図表Ⅱ-3-2-1 / 図表Ⅱ-3-2-3 で実測）。**直すべき表の崩れが存在しない。**
3. **座標再構成（XY-cut）を試作して実測した結果、正味で悪化する。** 円グラフ1枚は改善するが、**本物の表2つ・年表2ページ・目次4ページをすべて破壊する**。544ページ中543ページの本文が変化し、**現行行の22.9%が消失**する。

### さらに重要な発見: **Q12・Q15 の失敗原因の推定は誤っていた。**

`PHASE_A_IMPLEMENTATION_2026-07-26.md` §S06 は「Q12・Q15 は `Coverage@8=1.00` なのに要素カバー率 0.00 ＝ **純粋な生成側の失敗**（表・年表のレイアウト崩れ）」と分類していたが、**同じ retrieval JSON のアンカー方式が `anchor_coverage@8 = 0.00`（k=32でも0.00〜0.25）** を示している。

**必要な事実そのものが LLM に一度も届いていない。これは生成失敗ではなく、コンテキスト組み立ての失敗である。**

| 設問 | ページ方式 Coverage@8 | **アンカー方式 Coverage@8** | 実際の原因（本調査で特定） |
|---|---:|---:|---|
| Q12 | 1.00 | **0.00** | ①表のヘッダ行と数値行が別チャンクに分断 ②数値を持つ図チャンクが図表キャプションを失い検索不能 |

k=8 で「ページ方式1.00 / アンカー方式0.00」となるのは **Q12・Q15・Q18 の3問**であり、M1 が「生成失敗」に分類した設問と正確に一致する。**この3問は生成側ではなく検索・前処理側の課題である。**

### 1-4. ★本当の失敗原因（投入済みチャンクと実行時 `sources` の実物で特定）

#### Q15 — 文抽出クッションが年表を「索引行」と誤判定して破棄している

phys 23–24 は **1チャンク（595字, `pageNumber=23`）** に収まっており、gold 要素4件すべてを含む。ところが `sentenceCushion.js` の `splitSentences()` に掛けると:

```
[KEEP] len=76  （2024年度の国内外の出来事） 2024年度におけるわが国周辺の…「防衛この１年」として振り返ります。
[DROP] len=409 indexLike=true
```

**gold 要素4件を全部含む409字が、まるごと捨てられている。**

原因は目次・索引除去用のヒューリスティック:

```js
function looksLikeIndexEntry(sentence = "") {
  const digits  = (sentence.match(/[0-9０-９]/g) || []).length;
  const slashes = (sentence.match(/[／/]/g) || []).length;
  return slashes >= 1 && digits >= 8 && !/[。！？]/.test(sentence);
}
```

**年表の日付表記（`5/16` `7/26~8/12` `10/20`）はスラッシュと数字を大量に含み、句点を持たない。索引行（`非核三原則 ／ 196, 197`）と機械的に区別できていない。**

実行時 `sources` で裏付け済み。Q15 の source[0]（page 23）は**イントロ1文76字のみ**で、出来事は1件も含まれていなかった。

**検証（制御実験）**: 同じ system prompt・同じ `gemma4:12b`・temp=0 で、このチャンクを**フィルタせず**渡すと:

```

2. 7/26〜8/12：山形県酒田市および最上郡戸沢村などにおける大雨に係る災害派遣
3. 9/17：中国空母「遼寧」与那国西表間海域初航行
```

**「該当する情報はありません」という拒否から、時系列5件の列挙に変わる**（要素 e1 日米豪比 と e5 時系列5件 を満たす。0.00 → 0.25 相当）。残る誤りは `7/26~8/12`→山形県の取り違え（正しくはパリオリンピック、山形県は `7/31`）で、これは phys 23 の日付先出しレイアウトに起因する**二次的**な問題である。

## 2. タスク2: 座標（x/y）からの再構成は可能か

### 2-1. 仮説どおり座標情報は使えていない（事実）

現行 `PDFLoader/index.js:81-87` は `item.transform[5]`（y）を**厳密一致の改行判定にのみ**使い、`transform[4]`（x）は**完全に捨てている**。指示の指摘は正しい。

### 2-2. 3方式の再帰XY-cut を試作して実測した

scratchpad 上に、行生成→再帰的 XY-cut（水平の空白帯→垂直の空白列）を実装し、3変種を比較した。

| 変種 | phys 232 の円グラフ2枚を年度で分離できたか |
|---|---|
| 行単位 XY-cut（H優先） | ✗ V-cut が一度も発火せず、左右の図が同一行に混ざる |
| item単位 XY-cut（V優先 / H優先 / 最大ギャップ選択） | ✗ 同上 |
| **item単位 + ソフトV-cut**（またぐ item を3%まで許容） | **✓ 分離できた** |

**厳密な XY-cut が失敗した理由（実測）**: 2025年度側の最大 x は `退職金、`（x=334.6, w=29.6 → **x1=364.2**）で、2024年度側の最小 x は `施設整備費`（**x0=356.7**）。**たった1つのテキスト片が7.5pt はみ出しているだけで、x軸投影の空白が消える。** これは XY-cut の原理的な脆弱性であり、閾値調整では一般化しない。

「またぎ3%まで許容」は **phys 232 を見ながら決めた値**であり、他ページでの妥当性の根拠はない（＝過適合）。

### 2-6. タスク2の結論

> **座標からの行・列再構成は「技術的には一部可能」だが、「この製品に入れるべきではない」。**
>
> - 厳密なXY-cutは1つのはみ出し文字で破綻し、回避には**当該ページを見て決めた閾値**が必要（過適合）
> - 成功しても改善するのは円グラフ1枚と見出し分断だけ。**本物の表・年表・目次はすべて破壊される**
> - 影響範囲は全543ページ・現行行の22.9%消失。**Phase G が謳う「対象文書のみ・2.5人日・巻き戻し容易」の枠に収まらない**
> - そして**Q12・Q15 の実際の失敗原因ではない**

したがって**タスク3（実装）は実施しなかった。** ロードマップが用意していた「PDF表は非対応と明記するというスコープ管理も正しい判断」という退避路を取る。

## 3. 製品としての明記提案

### 3-1. 「PDFの表は非対応」ではなく、事実に即した書き方にすべき

実測の結果、「PDFの表が読めない」は**この文書に関しては誤り**である。図表Ⅱ-3-2-1 も図表Ⅱ-3-2-3 も、行×列が保たれた形で抽出できている。DTP製PDFの表はセルを行順に描画するため、pdfjs のコンテンツストリーム順がそのまま行順になるからである。

読めないのは**表ではなく図版（グラフ・インフォグラフィック）**である。したがって製品の注意書きは次のようにするのが正確である。

> **想定文書と対応範囲について**
>
> - **表（罫線のある一覧表）は、行・列の対応を保ったまま読み取ります。** 実測では防衛白書の予算比較表・15区分配分表とも、行と列が正しく対応した状態で取り込まれています。
> - **グラフ（円グラフ・棒グラフ）と、写真つきの年表・インフォグラフィックは対応していません。** これらは紙面上の位置関係で意味を伝える図版であり、テキストとしては数値やラベルの並びだけが取り出されます。**同じ紙面に複数のグラフがある場合、どの数値がどちらのグラフのものかを取り違えることがあります。**
> - グラフの数値を根拠にする必要がある場合は、**本文または表に同じ数値が記載されているか**をご確認ください。

### 3-2. ロードマップ Phase G の扱い

| 項目 | 提案 |
|---|---|
| **S36（HTMLの`<table>`）** | **保留。** 対象文書がPDFのみで、HTML文書が存在しない。着手するのは系統B（ヘルプ）がHTMLで入手できると判明してから |
| **S37 前半（表チャンクの行単位化 + 列ヘッダ付与）** | **実施すべき。ただし Phase G ではなく Phase E（チャンク構造化）として。** Q12 の実際の失敗の半分は「図表Ⅱ-3-2-1 のヘッダ行と数値行がチャンク境界で分断された」ことであり、これは S37 前半がまさに直す対象である |

## 4. 本調査が発見した、Phase G より優先度の高い2件

いずれも**本調査の実測で原因が特定済み**であり、Phase G の座標再構成（全543ページ書き換え）より圧倒的に小さく、圧倒的に効く。

### 提案1（最優先）: `looksLikeIndexEntry()` が年表・日付列を索引と誤判定する

- **場所**: `anything-llm/server/utils/vectorDbProviders/lance/sentenceCushion.js`
- **現状**: `slashes >= 1 && digits >= 8 && 句点なし` → **`5/16` `10/20` のような日付表記を持つ本文が索引扱いで全捨てされる**
- **影響の実測**: Q15 の gold 要素4件を含む409字がまるごと破棄され、回答が拒否になっている
- **修正案（例）**: 索引行の特徴は「**全角スラッシュ `／` の後にカンマ区切りのページ番号が続く**」ことなので、`／` に限定する・`[／/]\s*\d+(,\s*\d+)+` のようなページ番号列パターンを要求する、など判定を狭める。**日付パターン `\d{1,2}/\d{1,2}` は除外する**
- **注意**: このファイルは**他セッションの未コミット変更（cushion系4ファイル）に含まれる**ため、着手前に必ず差分を確認し、統合すること。本調査では**一切変更していない**
- **効果の見込み（制御実験の実測）**: Q15 は「拒否」→「時系列5件の列挙」に変わる
- **再embed**: 不要（検索後の処理）

### 提案2: 図表キャプションがチャンク境界で本体から切り離される

- **現象**: 図表Ⅱ-3-2-4 の数値を持つチャンクが、キャプション「防衛関係費の使途別分類（2025年度）」を隣のチャンクに奪われ、**dense でも BM25 でも当たらない**（`anchor_coverage = 0.00 @k=32`）。図表Ⅱ-3-2-1 でもヘッダ行と数値行が分断
- **これは Phase E（S37前半・チャンク構造化）の守備範囲**。「表・図表チャンクには必ずキャプション／列ヘッダを付与する」
- **再embed**: 必要（対象文書のみ）

### 提案3（評価基盤側）: `Coverage@k` のページ方式を単独で使わない

- **ページ方式は「そのページのチャンクが1つでも取れたか」しか見ないため、必要な事実を含まないチャンクでも 1.00 になる**
- k=8 で「ページ方式1.00 / アンカー方式0.00」＝ **Q12・Q15・Q18 の3問**。M1 が「生成失敗」に分類した設問と一致する
- **失敗モード自動分類は、ページ方式ではなくアンカー方式（またはAND条件）で行うべき**。そうすればこの3問は最初から「検索失敗」に分類され、Phase G に回されることはなかった
- 該当箇所: `scripts/complex-eval.py --phase retrieval` の分類ロジックと `PHASE_A_IMPLEMENTATION_2026-07-26.md` §2.5.3 / §S06 の記述
