## 0. 最初に読んでください（1分）

### これは何のための作業か

**自動採点器が「甘い方向」に間違っていないかを測ります。**
今の評価は「◯/20問」のような素の点数で報告していますが、採点器の感度・特異度が不完全だと
**この素の点数は必ずズレます**（arXiv:2511.21140）。特に我々は過去5件の採点欠陥のうち**4件が甘い方向**でした。
あなたが正解ラベルを付けてくれれば、以後は**ズレを補正した値**で報告できるようになります。

### 作業のかたち

| 項目 | 内容 |
|---|---|
| **全部で何件か** | **26件**（型1が17件、型2が9件） |
| **読む回答の数** | **9本**（型1で1周、型2でもう1周。同じ回答を2回貼ってあるので上に戻る必要はありません） |
| **所要時間の目安** | **約25分**（1件あたり40〜60秒＋回答を読む時間） |
| **書くこと** | 各項目の `- label: ` の行に **`YES` / `NO` / `?` のどれか1語**だけ |
| **中断・再開** | いつでも中断できます。**上から順に埋めてください。空欄が残っているところが続きです。**進み具合は各項目の `[n/26]` で分かります |
| **終わったら** | **「較正シート記入したよ」**とだけ言ってください。こちらでファイルを読んで集計します |

### 3つの注意

1. **「良い回答か」は聞いていません。**「その1点を述べているか／述べていないか」だけを見てください。
2. **迷ったら `?` を書いてください。**空欄のままにするより `?` のほうが助かります（`?` は集計の分母から外し、件数を別途報告します）。
3. **誤りを探そうとしないでください。**この作業は「甘い誤りがどれくらいあるか」を測るものですが、
   無理に厳しく付けると測定が逆方向に歪みます。**素直に読んで、見たままを書いてください。**

### 自動採点器の判定について

**自動採点器がどう判定したかは、末尾の「付録A」にまとめてあります。記入が終わるまで見ないでください。**
先に見ると、その判定に引きずられて（アンカリング）人手ラベルが採点器寄りに歪み、**測ろうとしているズレそのものが消えてしまう**ためです。

## 2. 判定の基準

### 型1（項目 1〜17）の問い

> **「この回答は、次の事実を述べていますか？」**

- **`YES`** … 述べている（言い方が違っても、**同じ内容を伝えていれば YES**）
- **`NO`** … 述べていない／違う値になっている／**別のものの事実として書いている**
- **`?`** … どちらとも言えない

**迷いやすいケースは、あらかじめこう決めてあります**（この表に従ってください）。

| こういうとき | 答え |
|---|---|
| 数値は合っているが表記が違う（`1万2,300円` と `12,300円` と `12300円`） | **YES** |
| 数値は合っているが、単位・名称の言い回しが違う（`月額約32,000円` と `約3万2千円`） | **YES** |
| 「AからBに変わる」型の事実で、**変更後のB**は正しく書いてあるが**変更前のA**が書いていない | **YES** |
| 「AからBに変わる」型の事実で、**変更後のBが違う値**になっている | **NO** |
| 数値は合っているが、**別の対象の数値として**書かれている（予備自衛官の額を即応予備自衛官の欄に書いている等） | **NO** |
| 「増額する」とは書いてあるが、肝心の**数値がない** | **NO** |
| 同じ主張の中に**正しい値と誤った値が併記**されている | **NO** |
| 回答が「記載がありません」「情報は含まれていません」とだけ答えている | **NO**（その事実を述べていないので） |
| 回答が長くて、述べているのか判断がつかない | **`?`** |

### 型2（項目 18〜26）の問い

> **「この回答は、次の“書いてはいけないこと”を書いてしまっていますか？」**

- **`YES`** … **書いてしまっている**（＝この点で誤りがある）
- **`NO`** … 書いていない（＝この点は問題なし）
- **`?`** … 判断がつかない

| こういうとき | 答え |
|---|---|
| 断定はしていないが、**読み手がそう受け取る**書き方をしている | **YES** |
| 書いてある内容自体は正しいが、**別の対象の見出し・区分の下に置かれている**（帰属の誤り） | **YES**（実務では誤情報になるため） |
| 「書いてはいけないこと」に似ているが、微妙に違う | **`?`** |
| 回答が「記載がありません」とだけ答えていて、余計なことを言っていない | **NO** |
| その話題に触れてすらいない | **NO** |

# 付録B — 記入後の TPR / TNR 算出手順

> 実装は本タスクの範囲外。**手順の定義のみ**をここに凍結する（事前登録。実行後にこの定義を変えない）。

## B-1. 用語

自動採点器を「YES / NO を出す二値分類器」とみなし、人手ラベルを正解とする。

|  | 人手 = YES | 人手 = NO |
|---|---|---|
| **自動 = YES** | TP | **FP（甘い誤り）** |
| **自動 = NO** | **FN（厳しい誤り）** | TN |

- **TPR（感度）= TP / (TP + FN)** … 「正しいものを正しいと言えるか」
- **TNR（特異度）= TN / (TN + FP)** … 「**誤りを誤りと言えるか**」← 本作業の主目的
- `?` と空欄は**分母・分子の両方から除外**し、除外件数を必ず報告する

型2（`[X]`）は極性が逆なので、**「回答に禁止された主張がある」を陽性**と定義して同じ表に落とす。
すなわち「人手 YES ＝ 誤りあり」「自動 YES ＝ 正規表現が発火」。
今回は自動側が全件 NO なので、**この層から得られるのは FN と TN のみ**＝`[X]` 検出器の **TPR** が測れる（TNR は測れない）。

## B-2. 重み（サンプリング設計に対応）

本シートは**二段抽出**である（付録C）。設問は等確率で選んだので設問レベルの重みは比の計算で相殺され、
**設問内の抽出率だけ**を重み `w` として掛ける。

`w = (その設問の required [N]/[E] 要素の総数) / (そのシートで判定してもらった件数)`

| 設問 | required [N]/[E] 総数 | 本シートの件数 | w |
|---|---|---|---|
| Q01 | 6 | 2 | 3.0 |
| Q03 | 7 | 2 | 3.5 |
| Q06 | 4 | 2 | 2.0 |
| Q07 | 6 | 2 | 3.0 |
| Q09 | 4 | 2 | 2.0 |
| Q11 | 4 | 2 | 2.0 |
| Q12 | 4 | 2 | 2.0 |
| Q13 | 5 | 2 | 2.5 |
| Q20 | 1 | 1 | 1.0 |

`[X]` は各設問に1件しかなく全件を採ったので **`w = 1`（重み付け不要）**。

## B-3. 算出式

```
TPR = Σ w·1[自動=YES ∧ 人手=YES] / Σ w·1[人手=YES]
TNR = Σ w·1[自動=NO  ∧ 人手=NO ] / Σ w·1[人手=NO ]
```

型1（`[N]/[E]`）と型2（`[X]`）は**別々に**算出する。混ぜない（測っている対象が違う）。
`[N]` と `[E]` の分離は本サンプルサイズでは行わない（各10件未満になり意味を持たない）。

## B-4. 信頼区間

**設問を単位としたクラスタブートストラップ**（設計書 `COMPLEX_QA_EVAL_SET_DESIGN_2026-07-26.md` §7 と同じ方式）。

1. 9設問から復元抽出で9設問を選び直す
2. 選ばれた設問に属する項目だけで TPR / TNR を再計算する
3. 2,000回繰り返し、2.5 / 97.5 パーセンタイルを 95% CI とする

`[X]` が 0件だった場合の上限は、**超幾何分布**で計算する（母集団18件から9件を抽出したため）。
「9件中0件」なら、母集団18件中の該当件数 K は **K ≤ 3（95%）**、
すなわち**見逃しハルシネーション率の95%上限は 3/18 ≈ 17%**。

## B-5. バイアス補正の適用（以後の全報告に適用する）

素の要素カバー率 `p_obs` を、**プラグイン補正**（Rogan–Gladen 型。arXiv:2511.21140 と同じ形）で置き換える。

```
p_corrected = (p_obs + TNR - 1) / (TPR + TNR - 1)
```

- `[0, 1]` の外に出たらクリップし、**クリップした事実を必ず併記**する
- **`TPR + TNR ≤ 1` なら採点器は情報を持っていない。** その場合は補正せず、**採点器を直してから測り直す**
- CI は「評価データのばらつき」と「較正データのばらつき」を**同時に**ブートストラップして合成する
  （較正側だけを固定すると CI が過小になる）
- 報告文には必ず `TPR = x.xx (95%CI …) / TNR = y.yy (95%CI …), 較正 n = 26, run 1, topN=8` を添える

## B-6. 事前に決めておく判断（結果を見てから変えない）

| 観測 | 取る行動 |
|---|---|
| 型1で **FP（自動YES・人手NO）が1件以上** | 素の要素カバー率にバイアスがあることが確定。以後 **bias-corrected 値＋CI でのみ報告**する |
| 型2で **YES（見逃したハルシネーション）が1件以上** | 「ハルシネーション率 0%」の報告を撤回。`[X]` の判定を**正規表現一致から claim の含意判定へ移す**設計変更（`RESEARCH_SCORING_AND_EXTRACTION_NOISE_2026-07-27.md` 推奨度A+）に着手する |
| 型1で **FN（自動NO・人手YES）が1件以上** | alias 辞書の不足。**alias を直して全条件を再実行**する（手動でのスコア補正は禁止。内部監査 §1-1） |
| **`?` が全26件の20%（6件）を超えた** | 要素の書き方が曖昧すぎる。要素定義そのものを見直す（JGLUE の「判定が揺れる設問は外す」に倣う） |
| `TPR + TNR ≤ 1` | 採点器を修正して**このシートを作り直す**。補正では救えない |

## B-7. この較正の適用範囲（限界の明示）

- 較正は **run 1（topN=8）の回答分布**に対するもの。**topN=4 など条件を変えた比較に流用する場合は、
  「採点器の誤り率は条件によらず一定」という仮定を置いている**ことを明記する。
  条件間比較を主張に使うなら、比較対象の run でも同じシートを作って確認する
- 較正データを作るのは**ユーザー本人**であり、「作成主体と検証主体が同一」問題は完全には解けない
  （`RESEARCH_EVAL_INDEPENDENCE_2026-07-27.md` §9 の注記どおり）。
  緩和されるのは**採点器の系統誤差**であって、**設問設計の盲点**ではない
- n=26 は「バイアスの有無を検出する」には足りるが、「補正後の値を高精度に出す」には足りない。
  補正値の CI が実用に耐えないほど広い場合は、付録C の未抽出プールから追加ラベルを取る

# 付録C — 対象の選び方（なぜこの26件で TPR/TNR が測れるのか）

## C-1. 母集団

保存済みの生成結果 `s06_gen_run1.json`（run 1・topN=8＝製品既定・20問）に対して
自動採点器が下した**決定的判定 97件**。

| 層 | 件数 | 内訳 |
|---|---|---|
| required `[N]/[E]` 要素 | **79件** | うち自動 YES 48件 / 自動 NO 31件 |
| `[X]` 要素 | **18件** | うち発火 **0件** / 非発火 18件 |

（`[P]` 26件は LLM-as-judge の担当であり、**既存の `JUDGE_CALIBRATION_HUMAN_SHEET_2026-07-26.md` が扱う**。本シートは対象外）

## C-2. 抽出手順（再現可能）

1. `[X]` 要素を持つ18設問を母集団とする
2. `random.Random(20260727).sample(..., 9)` で**9設問を等確率・無作為抽出** → Q01, Q03, Q06, Q07, Q09, Q11, Q12, Q13, Q20
3. 各設問の required `[N]/[E]` 要素から**無作為に最大2件**を抽出 → 17件
4. 各設問の `[X]` 要素は**全件**を採る → 9件
5. 合計 **26件 / 読む回答 9本**

**なぜ無作為なのか**: 「怪しそうな項目」を狙って選ぶと FP 率が構造的に過大に出て、
補正の基準として使えなくなる。率を推定する以上、層内は無作為でなければならない。

**なぜ設問単位のクラスタ抽出なのか**: 判定コストの大半は**回答を読む時間**であり、
要素単位で無作為抽出すると読む回答が20本に増えて所要時間が倍以上になる。
同じ回答から複数要素を判定すれば、**同じ時間で判定件数を増やせる**。
代償として項目間に相関が生じるが、これは付録B-4 のクラスタブートストラップで正しく扱える
（設計書 §7 が既に採っている方式と同じ）。

## C-3. なぜこの件数で足りるのか

**目的は「TNR の点推定値を精密に出すこと」ではなく、「素の点数を報告してよいかどうかを決めること」である。**

- **型1・自動YES層（10件）**: FP が **1件でも出れば**、素の要素カバー率にバイアスがあることが確定し、
  B-6 の行動が発動する。0件だった場合の 95% 上限は、母集団48件・標本10件の超幾何分布で **FP ≤ 11件（≒23%）**。
  「23%を超える甘さは無い」ことまでは言える（＝そこまでは TNR が保証される）
- **型1・自動NO層（7件）**: FN の検出用。ここは主目的ではないため小さく取っている。
  厳しすぎる誤りは**素の点数を過小評価させる**方向であり、我々の懸念（甘さ）とは逆向き
- **型2・`[X]`層（9件 / 母集団18件の50%）**: **これが本シートの主目的。**
  9件中0件なら、母集団18件中の見逃しは **K ≤ 3（95%、超幾何）＝ 17%以下**と言い切れる。
  `[X]` は 180回答すべてで一度も発火していないため、**現状この検出器の感度は完全に未測定**であり、
  人手ラベル以外に測る方法が存在しない。だから層別配分をここに厚くした
- **全79要素を人手で見る必要はあるか → 現時点では無い。**
  79件を全部読むと回答20本の通読が必要で 60〜90分かかる。一方、上の3つの層の結論
  （「バイアスがあるか / ハルシネーション検出器が働いているか」）は26件で出せる。
  **26件で「バイアスあり」と出たら、そもそも採点器を直してから測り直すので、79件の労力は無駄になる。**
  「バイアスなし」と出て、かつ補正値の CI が実用に耐えないほど広かったときにだけ、
  未抽出プール（`[N]/[E]` 62件・`[X]` 9件）から追加すればよい

## C-4. 既存シート（26要素）との重複回避

| | `JUDGE_CALIBRATION_HUMAN_SHEET_2026-07-26.md` | **本シート** |
|---|---|---|
| 測る対象 | **LLM-as-judge**（`qwen3.5:4b`）の判定 | **決定的採点器**（正規表現・alias一致） |
| 要素の型 | **`[P]` のみ**（26件） | **`[N]` / `[E]` / `[X]` のみ**（26件） |
| 出す指標 | Cohen's κ（judge 採用可否の判断） | **TPR / TNR**（バイアス補正のパラメータ） |

**要素の型が排他なので、項目の重複は構造的にゼロ**である。
実際に (run, 設問, 要素ID) の組で突き合わせても重複は 0 件（既存シートは `1/Q04/e1` などすべて `[P]` 要素、
本シートは同じ run 1 の `[N]/[E]/[X]` 要素）。
同じ設問（Q07, Q09, Q11, Q12, Q13, Q20）が両シートに出てくるが、**判定してもらう内容は別物**である。
