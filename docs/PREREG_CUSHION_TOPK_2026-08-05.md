## 1. なぜこれを試すのか（根拠のある仮説）

### 判明した機序

`sentenceCushion.js` の `topKSentences()` が **チャンク数に関わらず上位8文で固定**。

```js
function topKSentences() { const v = Number(process.env.SENTENCE_CUSHION_TOPK);
  return Number.isInteger(v) && v > 0 ? v : 8; }
ranked.slice(0, topKSentences())   // 全チャンクの全文をまとめて8文に絞る
```

**チャンクを増やすほど、1チャンクあたりに残る文が減る。**

### これで説明できた観測

| 観測 | 説明 |
|---|---|
| `anchor_coverage` が k に対し非単調（@8 0.7284 > @16 0.7105 > @32 0.7084） | 8文の枠を多数のチャンクで奪い合う |
| 165問中20問で @32 < @8 | 同上 |
| プールが同じ @16→@32 でも5問低下 | チャンク数が増えれば同じプールでも文が押し出される |
| `K=50 は retrieval では最高だが hakusho-eval が 29/30 → 27/30 に退行`（`server.env.template` の実測記録） | **この退行の機序がこれ** |

### 排除できた原因

- **パース不良ではない**: 取りこぼしたアンカー162個すべてが文書全文に存在
- **マルチホップの難しさではない**: ページの散らばり（0p 0.743 / 201p以上 0.729）と無相関
- **数値や表の問題ではない**: 取りこぼしの46%は「中程度の句」、純粋な数値は2%

## 2. 何を変えるか

**環境変数 `SENTENCE_CUSHION_TOPK` のみ。** コードは1行も変えない。

| 条件 | 値 |
|---|---|
| **A（対照）** | 8（現行の既定） |
| **B** | 16 |
| **C** | 24 |

**3条件のみとする。** 原則1「一度に複雑なことをやらない」に従い、
同時に topN やクッションON/OFF、リランカー等を動かさない。

## 3. 測り方

- 評価セット: 防衛白書30問（`scripts/hakusho-eval.py`）**各3run・交互実行**
- 併せて **TTFT を24問で測る**（文が増えればプロンプトが伸び、8秒要件に効くため）
- ワークスペース `emb-granite`（**再埋め込み不要**。クッションは検索後の処理なので
  ベクトルは変わらない）
- 出荷構成に固定: LLM `granite4.1:8b` / 埋め込み `granite-embedding:278m` /
  リランカー `japanese-reranker-xsmall-v2` / topN=8 / `openAiTemp=0` / `chatMode=query`
- 設問ごとに一意な `sessionId`
- 条件ごとにコンテナを作り直す（環境変数は起動時に読まれるため）

### 対照を測り直す理由

既存の 27/30 や 28/30 は**別ワークスペース・別時点**の値。
**条件の違う数値を比較して誤報告する事故を5回起こしている**ため、対照も同一手順で取り直す。

## 4. 合否基準（★測定前に確定）

### 採用条件（すべて満たすこと）

| # | 条件 | 根拠 |
|---|---|---|
| **P1** | 防衛白書30問の合計が**対照より増える**（+1問以上） | 精度向上が目的。同点なら変える理由がない |
| **P2** | **白書外（不明と答えるべき）5/5 を維持** | 文脈が増えると「無いことを答える」риск が上がる。1問でも落ちたら不採用 |
| **P3** | **TTFT の最大値が 8秒以内** | 顧客要件。中央値ではなく最大値で見る |
| **P4** | 空回答ゼロ | |
| **P5** | 3run の合計が**5問以上ばらつかない** | |

### 中止条件

- **C1**: P2 違反（安全性は精度で埋め合わせできない）
- **C2**: TTFT 最大値が 12秒を超える（改善幅に関わらず打ち切る）

### 判定に使わないもの

- `anchor_coverage`。**この指標自体がクッションの影響を受ける**ため、
  クッションを変える実験の評価に使ってはならない（今回の発見の直接の帰結）
- 統計的有意性（n=30 では検出力がほとんど無い）

### 同点だった場合

**対照（8）を据え置く。** 効果が無いなら変えない。

## 5. 事前に表明しておく予想（外れたら正直に書く）

- **B（16）が最良**と予想する。C（24）はプロンプトが伸びすぎて
  「文脈に埋もれる」ことで精度が落ちると予想
- **TTFT は 16 で 1〜2秒、24 で 2〜4秒伸びる**と予想する
- **白書外 5/5 は維持できる**と予想する（クッションは検索結果を絞るだけで、
  無関係な文書を持ち込むわけではないため）
- 改善幅は **+1〜+2問**と予想する。劇的な改善は期待していない
