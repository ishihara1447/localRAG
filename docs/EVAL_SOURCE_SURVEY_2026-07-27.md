それらは `page: null` / `phys` を正とする現行フィクスチャの方針をそのまま踏襲すべきである。

### 6-2. 桁境界を跨いで一致しうる数値

**現状の実装は保護されている**: `scripts/_eval_common.py` の `normalize_marked()` が空白を番兵 `\x00` として残し、

**残るリスクは「桁の包含」ではなく「桁の一致 × 単位の不一致」**である。alias から単位を落とすと別の量に当たる:

| 危険な数字列 | 出現する別文脈（phys） |
|---|---|
| `2,000` | 2,000円（phys 15, 443, 448）／200機（67,163,181）／200名（272,274,316） |

| `3,500` | 3,500両（109,111）／350機（224） |
| `5,000` | 5,000人（141,166,168）／500万円（234,236） |

**推奨**: `[N]` の value / alias には**必ず単位まで含める**（`12,300` ではなく `12,300円`）。

数値 `[N]` の判定に大量のノイズが混入しうる。**索引ページを gold から外すだけでなく、
`[N]` を含む設問では索引ページが上位に来ていないかを確認したほうがよい。**

**なぜ危険か**: `scripts/_eval_common.py:41` の `_WS = re.compile(r"\s+")` は Python の `\s` を使うが、

- **アンカーおよび `[E]` の value は、`\x08`/`\x07` を跨がない断片に切ること。** 特に上記24ページ＋18ページは要注意。

### 6-4. 図表の抽出順序が「視覚レイアウト順」で、ラベルと値が離れる

C3素材の主力である比較図表では、**値のブロックが先に並び、行ラベルのブロックが後にまとめて出る**。

例: 図表Ⅰ-3-3-3「中台軍事力の比較」（phys 108）の抽出結果は
`約204万人 / 約96万人 / …（中国の全値）… / 約2,360万人 / 1年` と値が続いたあと、
`中国 / 総兵力 / 陸上兵力 / 戦車等 / …` とラベルが出る。**どの値がどの行のものかはテキストからは復元できない。**

同様: 図表Ⅰ-3-4-1（phys 109、北朝鮮／韓国／在韓米軍）、図表Ⅰ-1-2（phys 48）、図表Ⅰ-1-3（phys 49）、図表Ⅱ-2-3-4（phys 224）。

**含意**:
- これらの図表は「**値そのものを問う設問**」には向かない（RAGが正答できなくても、それはRAGの欠陥ではなく抽出の欠陥）。
- 一方、**同じページの本文中に対比が言語化されている場合**（例: phys 109 冒頭「150万人程度の地上軍が厳しく対峙している」）は
  安全な素材になる。
- 図表Ⅰ-1-2（phys 48）は**上半分が地図型で順序崩壊、下半分が順位表（`1 インド 124` 形式）で健全**という混在型。
  **順位表部分だけを gold にすること。**
