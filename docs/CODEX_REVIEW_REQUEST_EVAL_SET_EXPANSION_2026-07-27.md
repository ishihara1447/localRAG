## 1. なぜ Codex にレビューを依頼するのか

**評価セットを作る主体と、評価されるシステムを改良する主体が、どちらも Claude Code である**という構造的問題があります。社内の内部監査（`docs/RAG_EVAL_INTERNAL_AUDIT_2026-07-16.md` §7-9）が「**作成主体と検証主体が同一**」を欠陥として既に指摘しています。

そして**これは抽象的な懸念ではなく、実際に事故が起きています**。

**採点の欠陥が5例連続で発生し、うち4例は「評価が甘い方向」＝システムを実際より良く見せる方向に間違っていました。**

| # | 欠陥 | 誤りの方向 |
|---|---|---|
| 1-2 | PDFの字間空白で `持ち込ま せず` が不一致 | 厳しい方向 |
| 3 | `70000円` が `約270000円` の内部に一致してYES判定 | **甘い方向** |
| 4 | 裸の `含まれて` が肯定文にも一致し、**ハルシネーションを「不明応答＝正解」と誤判定** | **甘い方向** |
| 5 | `予備自衛官手当` が `即応予備自衛官手当` の内部に一致し正誤を区別できない | **甘い方向** |

さらに、**チャット履歴の交絡でベースラインが実際より良く見えていた**事例もあります（生成側の過剰拒否が偶然打ち消されていた。`docs/EVAL_HARNESS_FIXES_2026-07-26.md`）。

**偶然とは考えにくい偏りです。** ユーザーからの指示もあり、**別主体による独立レビュー**を入れることにしました。

> **Codex に期待するのは「良い設問ですね」という承認ではなく、欠陥の発見です。** 特に**「この設問セットでは、システムが実際より良く見えてしまう」箇所**を厳しく指摘してください。

## 3. レビューしてほしい観点（優先順）

### 観点1（最重要）: 設問が原典に忠実か

各設問の `gold_pages` / `anchors` / `elements` が、**実際に原典PDFのその箇所に書かれている内容と一致しているか**。

- **存在しない記述を正解としていないか**
- **ページ番号がずれていないか**（**印字ページ番号と物理ページ番号が10ずれる**ことが判明しています。`PAGE_OFFSET=10`）
- アンカー文字列が原典に**逐語で存在するか**

### 観点2: 採点基準が「甘い方向」に壊れていないか

- **`[E]`（別名一致）の alias が、誤答も拾ってしまわないか。** 日本語には語境界の空白が無いため、**短い alias は長い語の内部に一致します**（欠陥5の類型）。`match.not_preceded_by` による排他語指定が必要な箇所が漏れていないか
- **`[N]`（数値）が桁境界を跨いで一致しないか**（欠陥3の類型）
- **`[X]`（禁止された主張）が、正しい回答にも発火しないか**（欠陥5そのもの）
- **`absence_proof`（文書に存在しないことの根拠）が本当に正しいか。** 「白書に無い」としている設問が、実は白書に書かれていないか

### 観点3: 設問セットとして偏っていないか

- **易しすぎる設問に偏っていないか。** LLMが作った設問は「モデル自身の得意分野に寄る」という既知の失敗モードがあります
- カテゴリ（C1 集約・構成 / C2 マルチホップ / C3 比較 / C4 要約 / C5 推論 / C6 unanswerable）の**バランス**
- **既知の失敗（Q02 の語彙ギャップ、Q12 の表分断など）が「解けるように」設問側で緩められていないか**

### 観点4: 統計的な妥当性

- 設問数80・要素数の目標（約320）が、**検出したい効果量に対して十分か**
- 現行20問では検出に失敗した実例があります（**要素79個・不一致9件で McNemar p=0.1797**）

## 4. 報告方法（Claude Code 側が確実に読める形式）

**保存先**: `fukugyo/codex-evaluations/` 配下（CLAUDE.md のマルチエージェント協調ルールに準拠）

| ファイル | 内容 |
|---|---|
| `codex-evaluations/2026-07-27_eval-set-expansion-review.md` | **レビュー本体** |
| `codex-evaluations/_latest.md` | **必ず更新してください。** Claude Code はここを最初に読みます |
| `codex-evaluations/_index.md` | 索引に1行追加 |

**指摘の種別**（CLAUDE.md の規定に準拠。**各指摘に必ず付けてください**）:

| 種別 | 意味 |
|---|---|
| `Action required` | **設問が原典と食い違う等、修正しないと評価が誤る**もの |
| `Watch` | 今すぐ修正不要だが、次回の判断時に確認すべきもの |
| `Opinion` | 設計上の見解。採否は Claude Code 側で判断する |

**指摘には必ず、設問ID（例: Q37）と、原典の該当箇所（印字ページ番号）を添えてください。** Claude Code 側が追試できる形にしてほしいためです。
