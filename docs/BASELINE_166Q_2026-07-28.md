### 1-4. 「この測定が妥当だった」と判断する条件（★事前定義）

すべて満たしたときに限り、本文書の数値を以後のベースラインとして採用する。

| # | 条件 | 満たさなかった場合の扱い |
|---|---|---|
| V1 | retrieval 2run が**完全一致**（設問×k×指標のすべて） | 不一致なら retrieval は「決定的でない」と記録し、run 平均ではなく**両runを併記**して以後の比較は同一run数で行う |
| V2 | generation 2run の**回答本文がバイト一致**、または3run目まで実施してレンジを報告 | — |
| V3 | 測定前後の MFT が**同一結果**（22 passed / 0 failed / 4 known） | 変化していたら測定中に採点器が動いた＝その測定は破棄 |
| V4 | 測定前後でワークスペース設定が `topN=8 / temp=0 / query` のまま | ずれていたら戻して再測定 |
| V5 | 全166問で回答が得られ、HTTP エラー・タイムアウトによる欠測が0件 | 欠測があれば件数を明記し、欠測問を除いた n で集計する |

### 1-6. 事前に決めた撤退・保留条件

- 全kで `anchor_coverage=0.00` の設問が **30問（18%）を超えた**ら、セット自体に系統的な欠陥があると判断し、
  **ベースラインとしての採用を保留**して欠陥の分類を優先する
- `[X]` の発火が **20問（12%）を超えた**ら、ハルシネーションではなく `[X]` 正規表現の誤発火を疑い、
  ハルシネーション率は「参考値」に格下げする
- V1（retrieval の決定性）が崩れたら、retrieval を主指標に据える前提（プロトコル §3-3）が揺らぐため、
  その事実を最上位の発見として報告する
