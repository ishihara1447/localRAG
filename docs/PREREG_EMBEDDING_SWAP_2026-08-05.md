## 1. なぜ測るのか

顧客要件「モデル・リランカーに中国系を使わない」に対し、**埋め込み `bge-m3`
（BAAI＝北京智源人工智能研究院）だけが未達**で残っている。LLM は granite4.1:8b（IBM）、
リランカーは japanese-reranker-xsmall-v2（日本）へ差し替え済み。

**埋め込みは変更すると全文書の再取り込みが必要**になるため、精度が落ちるなら
据え置いたほうがよい。落ちるかどうかを測るのが本測定。

## 2. 測る対象

| 条件 | モデル | 出自 / ライセンス | 次元 | サイズ |
|---|---|---|---|---|
| **現行（対照）** | `bge-m3` | **BAAI（中国）** / MIT | 1024 | 1,158MB |
| **候補A** | `granite-embedding:278m` | IBM（米）/ **Apache-2.0** | 未確認 | 562MB |
| **候補B** | `embeddinggemma:300m` | Google（米）/ **Gemma Terms** | 768 | 621MB |

### 候補を2つに絞った理由

- `snowflake-arctic-embed2`: Apache-2.0 だが**ベースが `BAAI/bge-m3-retromae`**。
  出自の要件に反する
- `multilingual-e5-large`: **著者が MSR Asia（北京）**。リランカーで mMiniLMv2 を
  同じ理由で却下した基準に反する
- `qwen3-embedding`: Alibaba（中国）
- `sarashina-embedding-v2-1b`: **非商用ライセンス**
- `cl-nagoya/ruri-v3-310m`: 性能は最有力（JMTEB 77.24）だが **Ollama 公式に無く**、
  コミュニティ GGUF は patched llama.cpp を要する。同梱方式が確立していない

**候補Bのライセンスは Apache-2.0 ではない**（Gemma Terms）。採用する場合は
配布物への同梱可否を別途確認する。**本測定は技術評価のみ**で、ライセンス判断は含まない。

### 前提工事（実施済み）

Ollama 埋め込みエンジンに接頭辞（prefix）対応を実装した（2026-08-05）。
**未実装のまま測ると、接頭辞を前提に学習された候補が不当に不利になる。**
変異注入で検出力を確認済み。

| モデル | 文書側 | クエリ側 |
|---|---|---|
| `bge-m3` | なし | なし |
| `granite-embedding` | 要調査（モデルカードで確認する） | 同左 |
| `embeddinggemma` | `title: none \| text: ` | `task: search result \| query: ` |

## 3. 測り方

**埋め込みを変えると既存ベクトルと互換性が無い。** 条件ごとに**別ワークスペースを作り、
同じ文書を再取り込みする**。現行の稼働ワークスペースには触れない。

- 文書: `R07zenpen.pdf`（令和7年版 防衛白書、544ページ）
- 検索評価: `scripts/_retrieval.py` による `anchor_coverage@4/@8/@16/@32`（166問）
- 生成評価: 防衛白書30問（`scripts/hakusho-eval.py`）**各3run・交互実行**
- 設問ごとに一意な `sessionId`、`openAiTemp=0` / `chatMode=query` / topN=8
- LLM は `granite4.1:8b` に固定（出荷構成に合わせる）
- リランカーは `japanese-reranker-xsmall-v2` に固定

### 対照を測り直す理由

既存の記録（`anchor_coverage@8 = 0.673`）は**別のワークスペース・別の構成**での値。
**条件の違う数値を比較して誤報告する事故を5回起こしている。** 対照も同じ手順で取り直す。

## 4. 判定基準（★測定前に確定）

### 採用条件（すべて満たすこと）

| # | 条件 | 根拠 |
|---|---|---|
| **P1** | `anchor_coverage@8` が**対照 −3pt 以内** | 検索が引けなければ生成は救えない。topN=4 の評価で検索 4.2pt 減が生成 3.74pt 減を招いた実例がある |
| **P2** | 防衛白書30問の合計が**対照 −3問以内** | LLM 差し替えと同じ幅 |
| **P3** | **白書外（不明と答えるべき）5/5 を維持** | 1問でも落ちたら不採用 |
| **P4** | 空回答ゼロ・捏造ゼロ | |
| **P5** | 3run の合計が**5問以上ばらつかない** | 測定が安定しないなら判断材料にならない |

### 中止条件

- **C1**: P3 違反（安全性は精度で埋め合わせできない）
- **C2**: 再取り込みが完走しない、または次元不一致で検索が動かない
- **C3**: 1問あたりの応答が中央値 60秒超

### 判定に使わないもの

- 統計的有意性（n=30 では検出力がほとんど無い）
- JMTEB 等の公開ベンチ。**候補Aは日本語データが存在せず、候補Bは評価が割れている**

### 同点だった場合の扱い

**P1〜P5 をすべて満たす候補が複数あれば、ライセンスが Apache-2.0 の候補Aを採る。**
候補B（Gemma Terms）は配布物同梱の可否確認が追加で要るため。

**どの候補も満たさなければ、`bge-m3` を据え置く。** 非中国系化は未達のまま残し、
その旨を顧客文書に明記する。**精度を落としてまで差し替えない。**

## 5. 事前に表明しておく予想（外れたら正直に書く）

- 候補A（granite-embedding）は**日本語で不利**と予想する。多言語モデルだが
  日本語の公開評価が無く、278M と小さい
- 候補B（embeddinggemma）は**接頭辞を正しく付ければ対照と拮抗**すると予想する
- **どちらも P1 を満たさない可能性が相応にある**（`bge-m3` は日本語検索で強い）

## 6. 記録するもの

- 条件ごとの `anchor_coverage@4/@8/@16/@32` と、その差
- 防衛白書30問の run ごとの生スコアとカテゴリ別内訳（**5カテゴリすべて。抜粋しない**）
- 実際に使った接頭辞（モデルカードの根拠つき）
- 再取り込みの所要時間とチャンク数、埋め込み次元
- 逸脱は全件記録する

## 8. 逸脱の記録（測定開始前・2026-08-05）

### 8-1. 接頭辞の一次情報が候補Bで確認できなかった

| 候補 | 接頭辞 | 根拠 |
|---|---|---|
| `granite-embedding:278m` | **なし** | モデルカード（`ibm-granite/granite-embedding-278m-multilingual`）に接頭辞の指定が無いことを確認。日本語（ja）が対応言語に明記されている |
| `embeddinggemma:300m` | 文書 `title: none \| text: ` / クエリ `task: search result \| query: ` | 🔴 **一次情報で再確認できなかった。** HuggingFace のモデルカードと `config_sentence_transformers.json` は **401（ゲート付き）**、Google 公式ドキュメントと Ollama ライブラリページのどちらにも接頭辞の記載が無い。`docs/EMBEDDING_NON_CHINESE_SURVEY_2026-08-04.md` の調査値をそのまま使う |

**したがって候補Bは、誤った接頭辞で測っている可能性が残る。**
候補Bが勝った場合は、採用前に接頭辞を一次情報で確認し直す。
候補Bが負けた場合も「接頭辞が誤っていたため」の可能性を排除できない旨を結果に明記する。

### 8-2. 候補Bはゲート付きモデルである（新規に判明）

HuggingFace で認証を要する（Gemma Terms）。**オフライン配布物への同梱可否は
ライセンス条項の確認が別途必要**であり、Apache-2.0 の候補Aより導入障壁が高い。
§4「同点ならApache-2.0の候補Aを採る」の根拠がさらに強まった。

### 8-3. 入力上限が候補で大きく違う（新規に判明）

| モデル | 入力上限 | 埋め込み次元 |
|---|---|---|
| `bge-m3`（対照） | **8192** | 1024 |
| `granite-embedding:278m` | **512** | 768 |
| `embeddinggemma:300m` | 2048 | 768 |

製品の `EMBEDDING_MODEL_MAX_CHUNK_LENGTH=500`（文字数）に対し、
**候補Aの 512 トークンは余裕が小さい**。日本語は1文字が1トークン以上になりうるため、
チャンクが切り詰められる可能性がある。切り詰めが起きたかは測定中のログで確認する。

**P1〜P5 の判定基準は変更しない。**
