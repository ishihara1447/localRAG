## 2. 工程C — 製品設定の変更（候補A採用の場合）

| ファイル | 変更内容 |
|---|---|
| `windows-native/config/server.env.template` | `EMBEDDING_MODEL_PREF=granite-embedding:278m`。接頭辞は**不要**（モデルカードに指定なし）なので `EMBEDDING_*_PREFIX` は設定しない |
| `windows-native/export-windows.ps1` | `$BundleModels` の `bge-m3:latest` を `granite-embedding:278m` に |
| `windows-native/service/LocalRAG-Ollama.xml` | サービス説明のモデル名 |
| `NOTICE` / `LICENSES/THIRD_PARTY_NOTICES.txt` | **BAAI bge-m3 を撤回済みへ、IBM granite-embedding を追加**（Apache-2.0） |
| `docs/MODEL_CARDS.md` | 埋め込みの節を全面差し替え |
| `CLAUDE.md` / `docs/HANDOFF.md` | 「embedding変更時は全文書の再embedが必須」の記述を最新化 |
| **fork（`anything-llm`）** | 接頭辞対応は既にコミット済み。**Windows 側 `C:\LocalRAG\src` への rsync が必要**（工程D） |

### 🔴 見落としやすい点

- **`bge-m3` は 1024次元、`granite-embedding` は 768次元。** 既存の導入先では
  **全文書の再取り込みが必須**。Release 本文の最上部に明記する
- **リランカーの入力上限が 512 トークン**（`bge-m3` は 8192）。本測定では切り詰め
  警告ゼロだったが、より長いチャンク設定にする顧客がいれば影響が出る

## 4. 判定の分岐（工程B）

### 候補Aが P1〜P5 をすべて満たす場合 → **採用**

そのまま工程C以降へ。**版数は v1.2.9**。

### 候補Aが落ちて候補Bが満たす場合 → **要検討**

候補Bは **Gemma Terms かつ HuggingFace ゲート付き**。配布物同梱の可否を
ライセンス条項で確認してからでないと採用できない。**この確認をユーザーに諮る。**

### どちらも満たさない場合 → **`bge-m3` を据え置く**

事前登録の「精度を落としてまで差し替えない」に従う。
**非中国系化は未達のまま残し、その旨を顧客文書に明記する。**
この場合、工程C以降は行わず、測定結果の文書化のみで終える。

### 🔴 P3（白書外 5/5）は絶対条件

文書に無いことを答えてしまうのは、精度低下より重い。
**1問でも落ちたら、他がどれだけ良くても不採用。**

## 5. リスクと、その扱い

| リスク | 影響 | 対処 |
|---|---|---|
| **既存導入先の再取り込み** | 全文書の再投入が必要。文書量によっては数時間 | Release 本文の最上部に明記。新規導入なら影響ゼロ |
| **配布物のチェックサム不整合** | `install.ps1` が停止し顧客がインストール不能 | 文書を直したら**必ずパッケージを作り直す**（Linux v1.1.2 と Windows v1.2.8 で2回踏んだ） |
| **結合スクリプトの不具合** | 顧客がインストールに到達できない | v1.2.8 で修正済み。**再ビルド後も実機で結合実証する** |
| **`.sha256` の同梱漏れ** | `Setup.exe` が起動直後に落ちる | `split-release.sh` に組み込み済み。**成果物で確認する** |
| **測定値の取り違え** | 顧客文書に誤った数値が載る（過去5回） | 対照は毎回同一手順で測り直す。**撤回済みの数値は `docs/WORKLOG.md` を確認してから引用する** |
| 8GB 実機が無い | VRAM 適合が最後まで未検証 | 埋め込みが 1,158MB → 562MB に減るため**VRAM には有利**。ただし実測はできない |
