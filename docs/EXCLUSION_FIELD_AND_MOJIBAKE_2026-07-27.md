# 増分1: `[E]`/`[X]` の照合に排他語フィールドを追加

## 1-1. 何を足したか

評価セットJSONの `match` に **`not_preceded_by`（配列）** を追加した。スキーマ版を `1.0` → `1.1` に上げ、`notes` に意味論を書いた（JSON単体で意図が読めるようにするため）。

```jsonc
{"id": "x1", "type": "X", "required": false,
 "claim": "予備自衛官と即応予備自衛官の数値を取り違えている",
 "match": {"regex": "即応予備自衛官.{0,16}12,?300|予備自衛官手当.{0,10}18,?500",
           "not_preceded_by": ["即応"]}}
```

**意味論**: 「一致した箇所の**直前**がこれらの語で終わっていたら、その一致は数えない」。
＝ 否定後読み `(?<!即応)` を、コードでなくフィクスチャ側から宣言的に足せるようにしたもの。

設計上の要点は4つ。

1. **回答全体ではなく一致の位置を見る。** 「回答のどこかに `即応` があれば無効」ではない。したがって、同じ回答に正しい表記と誤った表記が両方あれば、**誤った側だけが従来どおり検出される**
2. **一致が排他語の先頭から始まる場合はブロックしない。** `即応予備自衛官.{0,16}12,?300` が `即応予備自衛官手当（月額12,300円）` に当たるケースは直前に `即応` が無いので発火する。**同じ `[X]` の中の別の選択肢を巻き添えにしない**（重なり判定にすると巻き添えになるため、あえて「直前」に限定した）
3. **Layer0正規化した文字列どうしで比較する**ので、`即応 予備自衛官手当` のように空白・改行が挟まっても効く
4. **排他語を書かない要素は従来と完全に同一経路**を通る（`[N]/[E]` は `contains_marked()`、`[X]` は `finditer` の1件目＝`search` と同値）

## 2-3. 🔴 原因の実測 — 先行調査の前提が覆った

先行調査は「U+FFFD は `/ToUnicode` CMap 欠落が原因で原理的に復元不能、唯一の突破口はOCR」（PyMuPDF公式）を前提に、**再抽出（OCR）以外に手段がない**と結論していた。同調査自身が不明点6で「実際に ToUnicode 欠落なのかは要実測」と留保していた。**実測した結果、本PDFでは成り立たない。**

```
xref= 14651 basefont=NRBZZX+UDShinGoNTPr6N-Bold    type=Type0  /ToUnicode=True

```

### (2) PyMuPDF は同じページを U+FFFD ゼロで抽出する

| PDFページ | PyMuPDF の U+FFFD | PyMuPDF が返す文字 |
|---|---|---|

### (3) 犯人は抽出器（pdfjs-dist）である

collector が使う経路（`collector/processSingleFile/convert/asPDF/PDFLoader/index.js` → `pdfjs-dist@4.4.168` の legacy build、cMaps同梱）を**そのまま再現**したところ、同じページで U+FFFD が再現した。

> `/ToUnicode` は存在するので**情報は失われていない**。**OCR再抽出は不要**であり、
> 先行調査の推奨度A「不良ページのOCRフォールバック経路を用意」は、**少なくとも本PDFには当てはまらない**。
