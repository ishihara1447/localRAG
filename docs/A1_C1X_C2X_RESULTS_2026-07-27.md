**(3) 生成の実測**: Q04 の決定的要素は **4回の実行すべてで 4/4（完全正答）**。

**(4) では `page_coverage@8=0.50` は何だったのか — 計測アーティファクトである**

原因を実測で特定した。`PageIndex.locate()` は**文を「一致した文字数」で多数決**し、
**その文が始まるページ**に票を入れる。問題のチャンクは **phys 255 → 256 → 257 をまたいでいる**:

```
phys 255: 正規化後わずか 32字（「245 令和7年版 防衛白書 第5章 …」＝柱・ノンブルのみ）
phys 256: 正規化後わずか 57字（第Ⅲ部の扉。章題の羅列のみ）
phys 257: 1,446字（★gold本文）
locate() の投票 → {255: 291}  ＝ 291字の一続きが phys 255 の位置から始まると判定
```

**gold 本文（phys 257）は確かに取れているのに、チャンクの出所が phys 255 と判定され、
gold 257 との差が 2 で `PAGE_TOLERANCE=1` を超えるため「未取得」に数えられていた。**

これは **ページ方式が誤誘導する3例目**であり（既知の2例＝クッションのk非単調性の解釈、
Q12・Q15の失敗分類）、**A1 でアンカー方式に切り替えた判断を実データで裏づけている**。
実際、Q04 の `anchor_coverage@8` は **1.00**（3アンカーすべて rank1 で取得）である。
