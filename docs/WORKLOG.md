# WORKLOG — 作業の時系列記録（追記専用）

**このファイルは追記専用。過去のエントリは書き換えない。**
誤りが判明した場合も、古い記録を消さずに新しいエントリで訂正する
（「いつ何を信じていたか」が追えなくなると、同じ誤りを繰り返すため）。

## 読み方・書き方

| | `docs/HANDOFF.md` | `docs/WORKLOG.md`（本ファイル） |
|---|---|---|
| 形式 | 毎回**書き換える** | **追記のみ** |
| 内容 | 今どこにいるか・次に何をするか | 何を試し、何が失敗し、なぜそうしたか |
| 見るとき | セッション開始時にまず読む | 「なぜこうなっているのか」を遡るとき |

**セッション開始時は `HANDOFF.md` → 本ファイルの上から数エントリ、の順で読む。**

### 追記のしかた

```bash
scripts/worklog.sh "見出し" <<'EOF'
本文（markdown）
EOF
```

日時・ブランチ・git HEAD・未コミットの有無は自動で入る。

### 何を書くか

- **失敗と、その原因**（最重要。成功だけ書くと同じ失敗を繰り返す）
- 判断とその根拠（特に「やらないと決めたこと」とその理由）
- 撤回した数値・主張（撤回したことを明記する。後から誰かが再び引用するため）
- 外部に出したもの（Release 公開など、取り消せない操作）

### 何を書かなくてよいか

- コードの構造やコミット履歴から読み取れること
- 途中経過の細かい試行錯誤（結論と原因があればよい）

## 2026-08-04 19:32 — リランカーを非中国系へ差し替え、v1.1.2 をビルド（公開直前）

`main` @ `7cd0099` / 未コミットの変更あり

### 何をしたか

顧客要件「モデル・リランカーに中国系を使わない」に対応し、リランカーを
`BAAI/bge-reranker-v2-m3` → `hotchpotch/japanese-reranker-xsmall-v2`（MIT）へ差し替え、
配布物 v1.1.2 をビルドした。**Release 公開はまだ**（ユーザー承認待ち）。

- 精度: 同一条件A/B（各3run・交互実行）で 27/30 対 27/30、Δ=±0
  - 内訳では増減あり: 定義説明 5/6→6/6、直接事実 7/8→6/8、他3カテゴリ不変
  - **旧と新で答えが分かれたのは30問中2問だけ**。この規模では差を検出する力がほとんど無い
- リランク所要: 中央値 約4,400ms → 約500ms（**実測で約1/9**）
- 同梱サイズ: 571MB → 37MB

### 🔴 測定構成 ≠ 配布構成（未解決）

A/B 測定はイメージ `1.0.7` で行ったが、配布物は `1.1.0`。
実測で確認: `LANCE_HYBRID_RERANK` の出現数が 1.0.7 で **0**、1.1.0 で **1**。
配布構成ではリランカーの呼び出し回数が増えるため、**上記の精度・速度は
配布構成の値ではない**。配布構成での測定は未実施。

### 🔴 AVX2 依存が新規に入った（未検証）

同梱 ONNX は `model_qint8_avx2.onnx` をリネームしたもの。旧 bge は汎用
dynamic int8 で命令セット依存が無かったため、**本製品で初めて入ったハード依存**。
非対応環境では**エラーにならず静かに劣化する**可能性がある（未検証）。
`survey-target.sh` に検査項目5を追加して導入前に判明するようにした。

上流の変種は avx2 / avx512 / avx512_vnni / arm64 のみ。**AVX2 非対応の x86 CPU に
対する差し替え先は存在しない**ため、「別版へ差し替え可能」とは書けない。

### 失敗と原因（同じ轍を踏まないために）

1. **配布物を3回作り直した。** 文書を修正してパッケージへ反映する際、
   `checksums/package.sha256` を再生成しなかったため `install.sh` が整合性チェックで
   停止する状態になった。顧客はオフライン環境で12GBを再取得しても直らない。
   → **文書を1文字でも変えたらチェックサム再生成が必須。** 手順を守るだけでなく、
   `verify-package.sh` に検査項目 G（手順書の版数一致）を追加して機械的に捕まえるようにした。
2. **手順書が2版前のサイズを載せていた**（13,233,889,825）。v1.1.1 ですらない値が残留。
3. **`--version` がイメージタグまで動かしていた**ため、版数を上げるとビルドが停止した。
   `VERSION`（パッケージ版数）と `IMAGE_VERSION`（イメージタグ）を分離。
4. **`pkill -f '<文字列>'` が自分自身にマッチ**して launcher を殺した（複数回）。
   → プロセス確認は `ps -eo args | grep '[b]uild'` のブラケット記法か、成果物で判断する。
5. **待機ループの条件が早すぎた。** `[ -f MANIFEST.txt ]` は書き込み途中でも成立し、
   `[ -s ]` でも不十分だった（追記形式のため）。→ 完了マーカー（`join.sh` の生成＋
   全パートのハッシュ記録）で待つ。
6. **テストに検出力が無かった（2回）。** 実装を壊しても通るテストを書いていた。
   → 変異注入で FAIL することを必ず確認する。検査項目 G でも実施済み。

### 検証したこと

- `install.sh` の整合性チェックをそのまま実行 → 終了コード 0（44ファイル一致）
- `verify-package.sh` → 網羅性検証 PASS（検査項目 G を含む）
- **`join.sh` で結合を実証**（元ファイルを退避し、顧客と同じ手順で7分割から復元）
- 配布物に旧モデルの混入なし
