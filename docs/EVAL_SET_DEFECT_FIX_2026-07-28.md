### 2-2. ⚪ `Q07/e1`「ホットラインは計653件」 → **欠陥ではない**

**原典で確認した事実**

- 印字451 / 物理461 本文: 「防衛省・自衛隊では、隊員からの相談に対応するホットラインを設置しており、**2024年度は653件であった**。」
- 印字452 / 物理462 図表Ⅳ-3-4-2（防衛省ハラスメントホットライン相談件数の推移, 2024年度列）:
  パワハラ **581** / セクハラ **51** / マタハラ **21** / 各機関などの相談窓口 **769** / 合計 **1,422**
- 検算: 581 + 51 + 21 = **653**、653 + 769 = **1,422**。gold の6数値はすべて原典どおりで矛盾もない。

**判定の根拠**

1. gold「653件」は**原典に一字一句そのまま存在する**（コーパス実測: `653件` 1件）。
   設問「2024年度のハラスメント相談は何件ありましたか。**内訳もあわせて**」に対し、
   原典を読んだ人間が正しく答えれば「本文の653件（ホットライン3種）と図表の1,422件（各機関窓口を含む総数）」の
   両方に言及する。**満たせる要素であり、欠陥ではない。**
2. 診断レポートの提案（alias に「581・51・21 の同時提示」を追加）は**採用しない**。理由は2つ。
   - **表現できない**: `judge_element()` の alias は OR セマンティクスの部分一致であり、
     「3つが同時に出現したら YES」は書けない。実装するには `scripts/` の変更が必要で、本作業の禁止事項に当たる。
   - **仮に表現できても採ってはならない**: `e2`(581)・`e3`(51)・`e4`(21) がすでに独立に加点されている。
     その論理積を `e1` の合格条件にすると、**同じ事実で分子が機械的に +1 される二重計上**になる。
     79要素の独立性が壊れ、カバー率の意味が変わる。これは典型的な「採点を緩めて点を上げる」変更である。
3. **モデルの実回答**（実測、`gen_now_1.json`）は
   「2024年度のハラスメントに関する相談件数は、**合計で1,422件**です」＋内訳4行 であり、
   **653 にも「ホットライン分」という範囲の区別にも一切触れていない**。
   これは診断が (a-1) 抽出失敗に分類したものと同じ型であって、採点器の欠陥ではない。
   （人手較正で人が YES としたのは、`EVAL_PROTOCOL_2026-07-27.md` §0 が挙げる leniency bias で説明できる。
   人は 581+51+21 を暗算して補完したが、**モデルはその合算を述べていない**。）

> 補足: この判定は診断レポート §5-2 (b-1) の「採点器の欠陥として登録すべき1件」という結論を**採らない**。
> 差分を残す（`CLAUDE.md` マルチエージェント協調ルール）。恒久策は診断も述べているとおり
> `[X]`/`[N]` の claim 単位 judge 移行であり、alias の局所的な緩和ではない。
