### fork 再構成の制約（重要）

- **コミット履歴は復元不能。** この fork は設計上 `origin` を持たないローカル専用
  リポジトリで、改修コミットはどこにも push されていなかった。`.git` は
  Dockerfile が `COPY ./server` `COPY ./collector/` しか実行しないためイメージにも
  含まれない。
- したがって `versions.lock` の `fork_commit` は旧 `48c68662` ではなく
  **再構成コミット `8f4aacc`** になる。中身は同一である（15ファイルの
  SHA-256 一致で裏付け）が、履歴としての連続性はない。
- `docker/Dockerfile` は入手できていない（イメージに含まれないため）。
  `--skip-build` で足りる限り不要。**イメージを作り直す必要が生じたら
  upstream から取得すること。**
- `verify-image.sh` は今回**トートロジー**である。`server/` `collector/` を
  イメージから取り出したので、それをイメージと比較しても「ソース→イメージの
  忠実性」は検証できない。取り出しミスの検出には有効。

### podman だった場合について（誤記の訂正）

当初この文書と `INSTALL_GUIDE.md` に「podman だった場合は配布物の作り直しが必要」と
書いていたが、**これは誤りである**。`build-linux.sh` は `docker save` でイメージを
書き出しており、この形式は `podman load` がそのまま読める。モデル・リランカー・OCR
データは単なるファイルである。

**ランタイムに依存するのは制御スクリプトと compose ファイルのみ**:

| ファイル | 行数 |
|---|---:|
| `install.sh` | 732 |
| `uninstall.sh` | 283 |
| `docker-compose.yml` | 96 |
| `start.sh` / `stop.sh` | 57 |
| `systemd/ote-rag.service` | 23 |
| 合計 | **1,191** |

つまり作り直す対象は 12.3GB ではなく約 1,200 行であり、**12GB の再搬入は不要**。
この誤記は「先手を打って podman 版も作るべきでは」という判断を誘発していたため、
`INSTALL_GUIDE.md` とあわせて訂正した。

なお podman 版を先回りして作ることは、調査の結果**見送っている**。podman では
compose 経由の GPU 指定が無言で無視される既知問題があり（失敗が「エラー」ではなく
「静かに CPU 動作へ転落」として現れる）、開発機に podman が無い以上、一度も
動かせない実装を出荷することになるため。必要と判明してから着手する。
- **RHEL 9 実機での `install.sh` 通し実行**。開発機は WSL2 のため未検証のまま。
  初回導入がその実証を兼ねる。**なお WSL2 でも Docker と GPU は使えるため、
  SELinux・systemd・firewalld を除く大半は開発機で検証できる**（着手予定）。
- **導入先環境の事前調査**（`survey-target.sh` の実行）。docker か podman か、
  nvidia-container-toolkit の有無が未確定。**これが唯一のクリティカルパス**であり、
  toolkit が無ければランタイムに関係なく CPU 動作に転落して実用外になる。
- 監査（`docs/RHEL9_INSTALL_AUDIT_2026-07-29.md` は環境消失で失われた）で
  挙がっていた残りの指摘: 再インストール時の `.env` 上書き、アップグレード失敗時の
  systemd unit 復元、`verify-image.sh` の SKIP が合否に反映されない、など。
