### Phase 1: coarse-to-fine 二段化（最優先 / 再embed不要 / 中規模）

**内容**: 検索で当たったチャンクから**同一ページの全文を展開**し、そのページ内の文を reranker で再スコアして最終文脈を作る。

**なぜ最優先か**
- **理論上限が page_coverage = 0.946 になる。**現行 0.712 からの伸び代が全施策中で最大
- **再embed不要**
- 調査①がP1、調査②が順位1として**独立に同じ結論**に達している
- **自社実測がそのまま根拠**（「正解ページは取れている」）
- FEVER型の二段構成（document retrieval → sentence selection）は2018年以来の標準アーキテクチャ。FunnelRAG(2410.10293)も同枠組み

**リスクと対処**
- 文脈が長くなり **Lost in the Middle**（2307.03172）で生成側が落ちる → **必ず生成フェーズまで含めてA/Bで測る**
- 「要約・圧縮は数値情報を失う」（T²-RAGBench）ので、**削る方向ではなく足す方向が正しい**

**同時に入れる（費用: 数時間）**: 生成プロンプトで **数値の逐語コピーを強制し丸めを禁止**。T²-RAGBench のオラクル 72.3% は「**28%が生成側の失敗**」を意味する。FinanceBench では「正解 $1.577B に対し『約$1.5B』」が典型的失敗。

### Phase 2: 数値検索の強化（再embed不要 / 小〜中規模）

**2-a. 数値正規化した専用スパースフィールドの追加**（1週間以内）

インデックス側とクエリ側の**両方**に同じ前処理:
1. NFKC正規化（全角→半角）
2. 桁区切りカンマ除去（`4,000` → `4000`）
3. 漢数字スケール展開（`2兆5245億` → `2524500000000`）
4. 単位を別トークンで保持（`円`, `件`, `億円`, `人`, `年度`）
5. **元の表層形も併存させる**

既製部品の仕様が確立している: Lucene `JapaneseNumberFilter`（`兆六百万五千一`→`1000006005001`、`4,647.100`→`4647.1`）、Sudachi `JoinNumericPlugin`。

**必ず踏む落とし穴**（文書化済み）: クエリ側にも同じ正規化を適用しないと一切マッチしない / `discardPunctuation=false` が必須 / `15,7`→`157` バグ / 人名「京一」の誤正規化 / 大字・分数は非対応。

**2-b. RRF → 正規化スコアの凸結合（CC）＋数値クエリ検出時のsparse重み上げ**（2〜3日）

RRFは**順位のみ**を使うため、「BM25が完全一致で圧倒的スコア」という強い証拠が**順位変換で希釈される**。

```
BM25 1位 / dense 50位 → 1/61 + 1/110 ≈ 0.0255
dense 1位 / BM25 20位 → 1/61 + 1/80  ≈ 0.0289  ← 後者が勝つ
```

根拠: arXiv:2210.11934（TOIS）「**既存研究に反して RRF はパラメータに敏感**」「**CC はドメイン内外の双方で RRF を上回る**」「CC は少数サンプルで調整可能」。最適 α=0.3（2407.01219）。数値混在文書では「**BM25 が金融文書上で SOTA dense を上回る**」（2604.01733）。

### Phase 3: C6（回答不能）の強化 — 費用対効果が最も高い（1〜2日）

**C6 の 0.436 は「答えられないと判断する根拠すら取れていない」**ことを意味し、モデルが**捏造するか誤った理由で「不明」と答える**。ハルシネーション対策を掲げる製品として軽くない。

| 施策 | 費用 | 根拠 |
|---|---|---|
| **3-a. few-shot exemplar** — 「近い話題はあるが数値は書かれていない」実例を2〜4個プロンプトに入れる | **応答時間ほぼゼロ**（プロンプト長のみ） | **ELOQ: 2-shot で 13.89% → 62.39%（+48pt）**。調査3本で見つかった中で**最も費用対効果が高い単一の打ち手** |
| **3-b. 棄却促進システムプロンプト** | **コストゼロ** | AbstentionBench「精度を大きく損なわず abstention recall を改善」 |
| **3-c. 十分性判定の外部化**（取得文脈が「十分／近いが不十分／無関係」を先に判定） | LLM +1回 | Sufficient Context の selective generation で**回答時正答率 +2〜10%** |

**やってはいけないこと**: 「よく考えてから答えて」型のCoTを足す。**小規模モデルでは棄却判定に +1〜3pt しか効かない**（70Bは+22pt）。ELOQ。

**🔴 必須の同時対応**: **Abstention Precision（over-abstention）を計測に追加する。**
UAEval4RAG（ACL2025）が「**回答可能クエリと回答不能クエリの両方で最適な単一構成は存在しない**」と報告。**C6を上げるとC1〜C4が落ちるトレードオフが構造的にある。C6だけを見て調整すると、全体が「不明です」と答えるだけの製品になる。166問全カテゴリ同時計測が前提。**

**追い風**: AbstentionBench は **Llama 3.1 の 8B / 70B / 405B でほぼ改善なし**、RefusalBench も「規模も拡張推論も効かない」と報告。**gemma4:12b という制約は C6 において不利ではなく、設計次第でフロンティアモデルに並べる領域。**

### Phase 4: 索引時の仮想質問生成（2〜4日 + 生成バッチ / 再embed: 追加分のみ）

各チャンクに想定質問を3〜5個生成し、dense索引とBM25索引の**両方**に付与。

**当製品の制約に唯一完全に適合する高効果手法**:
- gemma4:12b をバッチで一度回すだけ。**推論時のLLM呼び出し増加ゼロ = 応答時間影響ゼロ**
- 追加のembedモデル不要
- **C5とC6の両方に効く可能性**（C5: 「航空自衛隊は今後どう変わるか」← 仮想質問「航空自衛隊の能力強化の方向性は何か」/ C6: 「可動率は何％か」← 「装備品の可動率をどう向上させるか」がマッチし近傍証拠が取れる）※**これは推論であり実測根拠はない**

**🔴 フィルタ必須**: Doc2Query--（ECIR2023）は「生成クエリには幻覚が多く、**フィルタで有効性+16%、実行時間−23%、索引−33%**」。**フィルタ無しは逆効果。**

代償: インデックス増（実務報告で最大5倍）、初回索引時間増、文書改訂時の再生成コスト。
**日本語・防衛白書での実証は存在しない。当製品で測るしかない。**

## 4. 調査間で見解が割れた点（どちらかを捨てず、両論を記録する）

### 4-1. 日本語SPLADE の採否

| 立場 | 主張 |
|---|---|
| 調査①（粒度） | **P4として推奨**。JQaRA で bge-m3+sparse 0.5088 → japanese-splade 0.6441（**+13.5pt**）。「具体的語句が取れない」症状に sparse 強化は筋が良い |
| 調査②（数値） | **期待値を割り引くべき**。学習済みスパース検索は「**稀なエンティティ、シリアル番号、型番など完全一致を要求するものが弱点**」。SPLADEはサブワード語彙で**桁の多い数値はやはり分割される**。JQaRAの差は一般語彙の改善であり数値に効く保証はない |

**判断（保留）**: 両者は矛盾しない（一般語彙には効くが数値には効かない）。**当製品の失敗の中心が数値である以上、Phase 2-a の数値正規化を先に入れ、その後の残差を見てから判断する。**

### 4-2. reranker は有害か

- 当製品は 2026-07-27 に `LANCE_HYBRID_RERANK` を有効化し、**集計で anchor_coverage +0.077** を得た（実測）。
- しかし T²-RAGBench では **reranker が Base RAG より悪化**（MRR@3 30.3 vs 36.9）。arXiv:2411.11767 は **bge-reranker-v2-m3 を被験モデルに含めて** 約半数の実験で K スケール時に retrieval 単独以下になると報告。
- **未分離。Phase 0 の D2（数値質問での層別）で決着させる。** 数値質問で有害なら、数値質問だけ reranker をバイパスする分岐を入れる。

## 5. 期待値の設定（過大な期待をしないために）

**「単一の手法で anchor_coverage が 0.71 → 0.9 に跳ぶ」という期待は持つべきでない。**

- 粒度のジレンマは**学界でも未解決**。CapRetrieval の著者自身が、細粒度を上げると全体意味理解が落ちるトレードオフを解けていないと明記
- 表+テキスト混在の数値QAは、**オラクル文脈でも 72.3%**（T²-RAGBench）
- TAT-QA では モデル 58.0% F1 に対し **人間 90.8% F1**（33pt差）
- 非英語は英語比で**平均19.4%の性能低下**（MULTITAT）

**現実的な打ち手は、page_coverage 0.946 という既に取れている資産を二段構成で刈り取ること（Phase 1）。**

## 6. 副次的な発見: 評価セット自体が資産になりうる

3本の調査が独立に同じことを指摘した。

- 「**正解ページは取れるが正解文が取れない**」を metric として明示的に分離した研究は**見つからなかった**。`page_coverage` と `anchor_coverage` を並べて報告する枠組みは標準化されていない
- **日本語での粒度ミスマッチの一次研究がほぼ無い**（CapRetrievalは中国語、Dense X/EntityQuestionsは英語）
- **日本語で「数値検索の失敗」を定量的に扱った一次文献は見つからなかった**
- BRIGHT に相当する**日本語の reasoning-intensive retrieval ベンチマークは存在しない**
- OmniDocBench に**日本語文書は含まれていない**

**当製品の166問セット（1,044要素 / 871決定的）は、日本語の複雑QA検索評価としてほぼ唯一の資産になり得る。**（※これは推測を含む評価）
