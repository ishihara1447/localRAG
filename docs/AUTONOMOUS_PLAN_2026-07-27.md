## 3. 【分岐C】(c)が最多 — クッションが検索改善を打ち消している

**該当条件**: 「anchorは検索で取れたが、クッション通過後のコンテキストには無かった」要素が、分類済み失敗の **1/3 以上**

**なぜ最優先か**: 検索側の改善（+24%）が**生成に届く前に捨てられている**ことになる。**上流で塞き止められている以上、下流に何を投じても無駄**。かつクッションは実装済みの機構なので、**再embed不要・変更が局所的**。

| # | 作業 | 完了条件 |
|---|---|---|
| **C1** | `sentenceCushion.js` の予算と、**リランク後に走る順序**を実装レベルで確認。「reranker が上げたチャンクを、クッションが文単位で落としている」経路を特定 | 落としている箇所と件数が実データで特定される |
| **C2** | **env gate 付き**で改善案を実装（候補: 予算をチャンク数連動にする／リランクのスコアをクッションに引き継ぐ／リランク済みチャンクは文単位の足切りを緩める）。**1案ずつ**試す | gate OFF で完全一致。gate ON の `anchor_coverage` と**コンテキスト到達率**を実測 |
| **C3** | ハルシネーションの退行確認 | **クッションOFFで 0/60→3/60 に増えた実測がある**（§2.5.9）。緩める方向の変更は**必ず捏造の増加を確認**する |

**次への判定**
- **要素カバー率が改善（3run一致で+3以上）** → 成功。gate を ON にする提案を作り、**承認待ちにする**（既定変更は自律範囲外）
- **改善が誤差範囲** → 分岐Bへ移る（測定が捉えられていない疑い）
- **ハルシネーションが増加** → **即時に中止**。クッションは忠実性のための機構であり、精度と引き換えにしない

## 4. 【分岐B】(b)が最多 — 測定が改善を捉えていない

**該当条件**: 「モデルは正しく述べているのに採点器が拾えなかった」要素が **1/3 以上**

**裏づけ**: 人手較正で **TPR = 0.875**（12.5%を取りこぼす）。**この分岐は既に部分的に実証されている。**

| # | 作業 | 完了条件 |
|---|---|---|
| **B1** | 取りこぼした要素を**型で分類**（表記ゆれ／単位／別名不足／要素定義が厳しすぎる） | 型別件数が出る |
| **B2** | **alias の拡充**で直せるものを直す。**`_eval_common.py` への一本化**も検討（同種の正規表現が4スクリプトに散在しているのが7〜8例目の欠陥の根因） | **`scripts/test_scoring_mft.py` が `--strict` で全PASS**（現在 KNOWN 4件） |
| **B3** | **保存済み回答を再採点**して要素カバー率を測り直す | **回答を再生成しない**（採点だけ掛け直す。生成側の条件を変えないため） |

**🔴 この分岐の危険**: **「採点を緩めて点を上げる」ことになりかねない。** 以下を厳守する。
- **alias 追加は「人手ラベルで YES と判定された実例」に限る**（`fixtures/calibration/scorer_human_labels_2026-07-27.tsv`）
- **人手ラベルが NO のものを拾うような変更は禁止**
- 変更後に**必ず MFT を `--strict` で回す**

**次への判定**
- **再採点で要素カバー率が上がる** → **見かけ上の停滞であり、実際は改善していた**。この事実を記録し、**過去の判断（特にK=50の却下）を再検証する**
- **ほとんど上がらない** → (b) は主因ではない。分岐Aへ

## 5. 【分岐A】(a)が最多 — モデルが証拠を使えていない

**該当条件**: 「証拠は届いているのにモデルが答えに含めなかった／拒否した／誤選択した」が **1/3 以上**

| # | 作業 | 完了条件 |
|---|---|---|
| **A1** | **oracle実験**: 正解チャンクだけをコンテキストに与えて生成させ、**モデルの能力上限**を測る（先行研究調査で標準手法か確認中） | 上限値が出る |
| **A2** | 上限で分岐（下記） | — |

**A1 の結果による分岐**

| oracle での要素カバー率 | 意味 | 次にやること |
|---|---|---|
| **≥ 0.85** | **モデルは証拠さえ届けば答えられる**。問題は届け方 | **分岐Cへ戻る**（コンテキストの作り方が原因）。検索指標が良いのに届いていない |
| **0.60〜0.85** | モデルの抽出能力に一定の限界 | 生成側の改善へ。**ただしプロンプトは2回連続で不採用**なので、**プロンプト以外**（抽出専用の中間ステップ等）を先行研究から選ぶ |
| **< 0.60** | **モデル自体の能力不足**が支配的 | **より大きいモデルの検討**を提案（要承認・VRAM制約あり）。検索側への追加投資は**打ち切りを推奨** |

**過剰拒否（a-2）が多い場合の特則**: 既知例 Q07（正解が rank 1,2,4,5 にあるのに拒否）。**プロンプトでの是正は2回失敗している**ので、**プロンプトを3回目に試さない**。先行研究調査の結果を待って手法を選ぶ。
