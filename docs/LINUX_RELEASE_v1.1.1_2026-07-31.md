### 訂正: `stop_grace_period` では exit 137 を防げない

E2E で `docker compose stop` が exit 137 になったため 30 秒へ延ばしたが、
**これは誤診断だった。**

`anything-llm/docker/docker-entrypoint.sh` に `trap` が無く、PID 1 の bash は
カーネル仕様により既定動作のシグナルを配送されない。SIGTERM は node に届かず、
猶予満了で SIGKILL になる。猶予を延ばしても解決しない。

設定自体は残した（将来 entrypoint を直したときに猶予不足で切られないため）が、
「データ破損の余地に対処した」という当初の説明は誤りである。compose の
コメントと Release 本文に、未解消であることを明記した。

**根本対処**: entrypoint に SIGTERM を子へ転送する trap を入れ、イメージを
再ビルドする。`docker/Dockerfile` が未入手のため別途対応とした。

## 4. テストの検出力（レビュー指摘 B7）

既存41ケースは、**今回の3コミットをまるごとリバートしても全 PASS だった**。
`install-wiring-test.sh` が `--data-dir` と `--no-systemd` を全ケースで固定しており、
引き継ぎ経路と systemd 経路を一度も通らないためである。

対応:

- 両オプションを可変にした（`NO_DATA_DIR=1` / `WITH_SYSTEMD=1`）
- 4ケースを追加（計9ケース、全体で45ケース）
- ミューテーション解析で、引き継ぎ削除・危険値許可・unit 復元削除・退避失敗の無視を
  **すべて検出できることを確認**

なお追加した「危険なデータ領域は中止する」は、当初**終了コードだけを見ていたため
ガードを外しても偽 PASS になった**（非 root で `/` に書けず別の理由で exit 1 になる）。
停止理由まで確認するよう修正している。

## 6. 作業中に起きた事象

### 6-1. Docker イメージ2つが消失（原因未特定）

作業中に `localrag-anythingllm:1.1.0` と `ollama/ollama:0.30.11` が消えた。
古い版（1.0.0〜1.0.7、`ollama:latest`）は残っており、**新しいものだけが選択的に
消えている**。ディスクは 645GB 空きで、容量圧迫による自動削除ではない。
`docker events` に削除記録は無く、こちらの操作でもない。

7/29 にホームディレクトリが初期化される事象が起きており、同種の環境巻き戻しが
再発した可能性があるが**推測の域を出ない**。

**復旧は容易だった**: 配布物パッケージの `images/*.tar.gz` から `docker load` で
1分。ID も記録と一致し、`verify-image.sh` も PASS した。

🔴 **ただし構造的な弱点が残っている**: イメージを作り直すには `docker/Dockerfile`
が要るが、これは fork 再構成時にイメージから取り出せなかった（Dockerfile は
イメージに含まれない）。現状は**イメージを失うと配布物からしか戻せない**。
upstream から取得しておくべきである。

### 6-2. 判定を誤った事例（再発防止のため記録する）

本セッションで、間接的な指標に頼って誤判断した事例が複数あった。

| 事例 | 原因 |
|---|---|
| 待機ループが6〜7時間空回り（2回） | `pgrep -f '<文字列>'` が**自分自身のコマンドラインにマッチ**して終わらない |
| 監視が「完了」を誤報（2回） | フィルタに `完了` という一般語を入れ、別の行を拾った |
| 「配布物が消えた」と誤認 | 親ディレクトリで `ls` していた（`cd` の持続を失念） |
| 「7件すべて不一致」と誤報 | `cd` が失敗し、比較対象のファイルを読めていなかった |

いずれも**成果物を直接見れば**即座に分かるものだった。プロセスの生死やログの
文字列ではなく、生成物の存在・サイズ・ハッシュで判定すべきである。
