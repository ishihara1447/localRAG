# 調査: 推論質問(C5)・回答不能判定(C6)の既知解法

調査日: 2026-07-28
対象: OTE-RAG（bge-m3 + hybrid + bge-reranker-v2-m3 + chunk500 + gemma4:12b、完全オフライン）
実施: researcherサブエージェント（Write権限が無かったため本ファイルはClaude Codeが保存）

## サマリー

- **C5は「reasoning-intensive retrieval」という既知の研究領域**。BRIGHTベンチマークが同じ現象を定量化（MTEB 59.0 → BRIGHT 18.3 nDCG@10）。有効打はクエリ側の推論展開（最大+12.2 nDCG）と索引側の仮想質問生成で、後者は**応答時間コストがゼロ**。
- **C6は検索単独では解けない**。Sufficient Context / AbstentionBench / RefusalBench が揃って「文脈が十分でも小規模モデルは失敗する」「モデル規模を上げても棄却能力は改善しない」と報告。**生成側の明示的な十分性判定**が必須。かつ小規模モデルではCoTが効かない（ELOQ: 70Bは+22pt、小規模は+1〜3pt）。
- 最優先は手法導入ではなく**計測の妥当性検証**。

## 0. C5とC6は別の故障モード

| | C5 推論・含意 | C6 回答不能 |
|---|---|---|
| 一次的ボトルネック | **検索**（語彙ギャップ） | **生成の判断**（+近傍証拠の検索） |
| 対応領域 | query decomposition / expansion / reasoning retrieval | abstention / selective generation / context sufficiency |
| モデル規模の効き | 大規模ほど分解の質が上がる | **規模はほぼ効かない**（AbstentionBenchが明確に否定） |
| 索引時対策 | 可（仮想質問生成） | 一部可 |

## A. C5（推論・含意）の検索

### A-1. BRIGHT ベンチマーク — これは既知の問題領域

質問と根拠に語彙の重なりが無い検索は **reasoning-intensive retrieval** と呼ばれる。

- BRIGHT（1,384クエリ）。MTEB首位だった **SFR-Embedding-Mistral が MTEB 59.0 → BRIGHT 18.3 nDCG@10** と40pt以上落ちる（arXiv:2407.12883）。
- **クエリについて明示的に推論させると最大 +12.2 ポイント改善**。

**含意**: C5の 0.471 は実装バグではなく**埋め込みモデル全般の既知の限界**。bge-m3 を差し替えても解決しない可能性が高い。

### A-2. Query decomposition

| 手法 | 報告改善幅 | 条件 | 小規模での実証 |
|---|---|---|---|
| IRCoT (ACL2023) | 検索 最大+21pt、QA 最大+15pt | GPT-3 | Flan-T5-large でも同様と主張（arXiv:2212.10509） |
| Self-Ask | Bamboogle 17.6→57.6、2Wiki 25.4→40.1 | GPT-3 davinci-002 | **15B未満の検証なし** |
| DSP | vanilla比 +37〜120%（相対） | GPT-3.5 | なし |

**重要な反証（ローカル7Bでの実測）** — arXiv:2606.21553（Qwen2.5-7B, HotpotQA 5,000問）:

| 除去した要素 | EM変化 | 有意性 |
|---|---|---|
| クエリ分解を除去 | **-1.4%** | p=0.004 |
| クロスエンコーダreranker除去 | **-1.7%** | p<0.001 |
| 検索を1ステップに制限 | **-7.1%** | p<0.001 |
| **適応ルーティング→固定hybrid(RRF)** | **+1.8%**（固定の方が良い） | p<0.001 |

レイテンシ: ベースライン546ms → 分解なしエージェント2,546ms → **フル5,642ms**。

論文の結論「**クエリ分解は精度を上げるがレイテンシを倍増させ、レイテンシ制約下では最初に外すべき候補**」「rerankerはコストほぼゼロで効くので常時入れるべき」「ルールベースの適応ルーティングは固定hybridに劣る」。

→ **当製品はすでに固定hybrid+RRF+rerankerで、この論文の推奨構成と一致している。**

### A-3. HyDE / Query2doc

- **HyDE**（ACL2023）: TREC DL19 nDCG@10 61.3、SciFact 69.1。前提は「**教師なし検索器のゼロショット改善**」。**bge-m3 は学習済み多言語retrieverであり、HyDEの利得が最大化する条件を満たしていない。**
- 反証: 「SQuADでは効くがBiPaRでは苦戦」「事実質問では仮想回答が正解そのものになり性能が人為的に嵩上げ」（二次情報）。
- **Query2doc**（EMNLP2023）: 擬似文書を**元クエリに連結**。BM25を **+3〜15%** 改善。元クエリを捨てないため**HyDEより安全**。

**C5でのHyDEの弱点（推論、実測根拠なし）**: 「航空自衛隊は今後どう変わるか」に対しgemma4:12bが生成する仮想回答は白書に無い一般論になりやすく、外れれば検索を汚す。**C5でこそリスクが最大化する。**

### A-4. Step-back prompting

| データセット | ベースライン(PaLM-2L) | Step-Back | +RAG |
|---|---|---|---|
| MMLU Physics | 66.4 | **73.2** | — |
| MMLU Chemistry | 70.9 | **81.8** | — |
| TimeQA | 41.5 | 66.0 | **68.7** |
| MuSiQue | 35.5 | — | **42.8** |

**制約**: 評価モデルは **PaLM-2L / GPT-4 / Llama2-70B のみ。小規模モデルの評価なし。**
**負の情報**: 残存エラーの90%以上が推論ステップで発生。**新たなエラーを5〜12%の率で持ち込む**。

→ **LLM呼び出し1回追加と非常に安価**で、C5の質問形式とは相性が良い。**A/Bで測る価値が最も高い低コスト手法。**

### A-5. 索引時の仮想質問生成（応答時間コスト = ゼロ）— 本命候補

- **Doc2Query--**（arXiv:2301.03266）: 生成クエリをフィルタすると **有効性最大+16%、実行時間−23%、索引−33%**。
  → **「生成質問をそのまま全部入れると悪化する。フィルタ必須」**という反証込みの知見。
- HyQE（EMNLP2024）は**推論時**に走る方式で索引時ではない。改善数値は**不明**。
- Question-Based Retrieval using Atomic Units（arXiv:2405.12363）: PDFパース不能で数値**不明**。

**当製品への適合度が最も高い理由**:
1. gemma4:12b をバッチで一度回すだけ。**推論時のLLM呼び出し増加ゼロ = 応答時間影響ゼロ**
2. 追加のembedモデル不要
3. dense側とBM25側の**両方**に効く
4. C6にも効く可能性がある

### A-6. Self-RAG / FLARE の小規模モデル実測 — 強い反証

arXiv:2406.12534（Llama2上での再実装比較）:

| 手法 | Llama2-7B | Llama2-13B |
|---|---|---|
| Never-Retrieve | 43.10 | 44.39 |
| **Always-Retrieve（単純RAG）** | **49.23** | **52.09** |
| **Self-RAG** | **35.98** | **37.60** |
| **FLARE** | **48.50** | **48.90** |

- **Self-RAG は 7B/13B で「検索しない」より悪い**（35.98 < 43.10）。
- **FLARE は単純な always-retrieve に負ける**。不確実性推定がキャリブレーションに依存し、**小規模モデルには適応困難**。

→ **当製品（gemma4:12b、fine-tune不可）では Self-RAG も FLARE も採用すべきでない。**

## B. 回答不能判定（C6）

### B-1. Sufficient Context（ICLR2025, arXiv:2411.06037）

- 文脈が十分な割合: FreshQA 77.4%、HotpotQA 46.2%、Musique 44.6%
- **大規模モデル**: 十分な文脈では80%超。しかし**文脈が不十分なとき棄却せず誤答する**
- **小規模モデル（Mistral 3 / Gemma 2）**: **十分な文脈があっても幻覚するか、あるいは棄却してしまう**
- HotpotQAで「文脈不十分」の **35%以上でモデルが正答**（パラメトリック知識で答えている＝RAG評価を歪める）
- **selective generation**（自己確信度＋文脈十分性シグナル）で**回答時正答率 +2〜10%**
- 十分性オートレイターは人手ラベル115件に対し **93%の精度**

**含意**: gemma4:12b は「小規模モデル」側の挙動をする可能性が高く、**anchor_coverage を上げても C6 が自動的に直る保証はない**。しかし**十分性判定を外部化すれば +2〜10% の改善余地がある**。

### B-2. AbstentionBench — 「規模を上げても棄却は改善しない」

arXiv:2506.09038（20データセット、35,000問超）

- **モデルサイズは棄却性能にほぼ影響しない。** Llama 3.1 の 8B / 70B / 405B でほぼ改善なし。**通常のスケーリング則と真逆。**
- **推論fine-tuningは棄却を悪化させる**（平均 **24%低下**）。
- Qwen 2.5 32B や Llama 3.1 8B は GPT-4o / Gemini 1.5 Pro と**同等の棄却性能**。
- **棄却を促すシステムプロンプトは、精度を大きく損なわずに abstention recall を改善する**（安価な打ち手）。

**含意**: 「大きいモデルを使えばC6は直る」は否定された。**逆に gemma4:12b でも設計次第でフロンティアモデル並みの棄却性能は達成可能。当製品にとって強い追い風。**

### B-3. RefusalBench（EACL2026, arXiv:2510.10390）

- 6カテゴリ・176種の摂動戦略。30以上のモデルを評価。
- **複数文書タスクでは refusal 精度が 50% を下回る。**
- **モデル規模も拡張推論も改善しない**（AbstentionBenchと一致）。
- refusal は「検出」と「分類」から成り、**学習可能・アライメント感受性のある能力**。
- ※二次情報にあった「Claude-Sonnet-4 の over-abstention 率 0.259」は**本文から確認できず。出典不明として扱うこと。**

### B-4. ELOQ（SIGIR2025, arXiv:2410.14567）— C6に最も実務的な数値

| 設定 | 精度 |
|---|---|
| Llama 8B 基本プロンプト | 約69% |
| Llama 70B 基本プロンプト | 約70% |
| **Llama 70B + Zero-shot CoT** | **91.97%（+22pt）** |
| **小規模モデル + Zero-shot CoT** | **+1〜3ptのみ** |
| **GPT-3.5 + 2-shot プロンプト** | **13.89% → 62.39%（+48pt）** |
| Llama 3.2 3B 学習済み分類器 | 70Bの直接プロンプトに匹敵 |

**最重要の2点**:
1. **小規模モデルにCoTを足しても棄却判定はほぼ改善しない（+1〜3pt）。**
2. **few-shot exemplar の効果が桁違いに大きい（+48pt）。**「近い話題はあるが数値は書かれていない」実例を2〜4個プロンプトに入れるのが最も安価で最も効く。

### B-5. Chain-of-Note（EMNLP2024, arXiv:2311.09210）

- **完全にノイズな文書下で EM 平均 +7.9**
- **事前学習知識外の質問に対する棄却率 平均 +10.5**
- **LLaMA-2 7B に fine-tune**。GPT-4 ではプロンプト調整のみで有効。

→ C6に直接効く数少ない実証済み手法で **7B規模での実測がある**。ただし**プロンプトのみで12Bが同等に動くかは不明**。出力トークン増で応答時間は増加。

### B-6. negative evidence retrieval

**この問題設定を直接扱った研究は見つからなかった。** 近い領域:

- **Ruling Out to Rule In**（arXiv:2604.04593）: 医療QAで「除外診断」を模し**正の証拠と並んで負の証拠を検索**。数値**不明**（PDFパース不能）。概念的に最も近い。
- **Evidence Absence Is Not Evidence Insufficiency**（arXiv:2605.26663）: **証拠の不在と証拠の不十分は別物**であり、既存データセットは両者を混同。モデルは「検索で何も出なかった＝NEI」というショートカットを学習し実運用で崩壊する。推奨は「不在と不十分を明示的に分離」「検索可能だが決定的でない証拠を十分に含める」。

→ **当製品のC6アンカー設計（「答えられないと判断するために必要な近傍の記述」をアンカーとする）が文献的に正しい方向であることを支持している。** 製品の評価設計上の強みとして主張できる。

### B-7. UAEval4RAG（ACL2025）— 重要な警告

- 6カテゴリの回答不能要求を自動合成。指標は unanswered ratio / acceptable ratio。
- **主結論: 回答可能クエリと回答不能クエリの両方で最適な単一構成は存在しない。**

**含意（重要な警告）**: C6を改善しようとすると **C1〜C4（回答可能側）の精度が落ちる**トレードオフが構造的に存在する。**C6改善策は必ず全カテゴリ同時計測で評価すること。**

### B-8. 評価方法 / over-abstention の測り方

- 標準指標は **Abstention Precision / Recall / F1 + Response Accuracy**。over-abstention は「Abstention Precision の低下」として現れる。
- LLM-as-judge の妥当性: AbstentionBench 88%、Sufficient Context 93%、ELOQ 94.91%。**人手検証100件程度で判定器の精度を先に測るのが標準作法。**

**当製品の計測の欠落**: 現在の `anchor_coverage@8` は**検索側しか見ていない**。最低限
- Abstention Recall（回答不能問で正しく棄却できた割合）
- **Abstention Precision（回答可能問で誤って棄却しなかったか）** ← over-abstention

の2軸が必要。**これが無いと、C6を改善したつもりで全体が「不明です」と答えるだけの製品になる。**

## D. C5とC6は同じ打ち手で改善するか

**結論: 部分的に共通するが、主要な打ち手は別。**

**共通して効くもの**
1. **検索深度の拡大 + rerankerへの委譲** — 検索深度が最大の支配要因（1ステップ制限で -7.1 EM）。両方に効く。
2. **索引時の仮想質問生成** — C5: 「航空自衛隊は今後どう変わるか」← 仮想質問「航空自衛隊の能力強化の方向性は何か」がマッチ。C6: 「可動率は何％か」← 「装備品の可動率をどう向上させるか」がマッチし**近傍証拠が取れる**。※**推論であり実測根拠はない。**

**C5固有**: クエリ側の推論展開（step-back / query2doc / 分解）。C6には効かない（むしろ「定員は何人か」を分解すると余計に無関係文書を引く可能性。**推測**）。

**C6固有**: 生成側の十分性判定、few-shot exemplar、Chain-of-Note、棄却促進システムプロンプト。

**最も重要な非対称性**: C5は検索が直れば改善する見込みが立つ。**C6は検索が直っても改善しない可能性がある**（小規模モデルは十分な文脈でも失敗する）。C6は「検索改善」と「生成側の判定強化」の**両方**が必要。

## E. 適用優先順位（費用 × 期待効果）

### 優先度1: 計測の妥当性検証（数時間 / 応答時間影響なし）

- **BM25の日本語トークナイザを確認する。** C6アンカー「高い可動率を支えることのできる能力」は質問文「可動率は何％」と**「可動率」が完全一致**している。にもかかわらず取れていないなら、BM25が機能していない疑い。**実装バグの可能性**であり、手法を入れる前に潰すべき。（**推測**。コードは未確認）
- **チャンク境界によるアンカー分断の確認。**
- **C6の13問 × top-8 を目視。**「近傍証拠が全く無い」のか「3位以内にあるが表記が一致しない」のかで打ち手が180度変わる。
- 根拠: NEI artifact論文（2605.26663）が「評価データ構成のアーティファクトが性能の錯覚を生む」と警告。n=17, n=13 という小サンプルでは尚更。

### 優先度2: 検索深度の拡大 + reranker委譲（実装ほぼゼロ / +数百ms / 効果 中〜高）

候補数を50〜100に拡大し reranker で top-8 に絞る。根拠: 検索深度が最大の支配要因、rerankerはレイテンシほぼゼロで +1.7 EM。**C5・C6の両方に効き、実装コストが最も低い。**

### 優先度3: C6専用 — few-shot exemplar + 明示的十分性判定（1〜2日 / 効果 高）

- **3-a. few-shot exemplar**（応答時間ほぼゼロ）: 根拠 ELOQ 2-shot で **13.89% → 62.39%（+48pt）**。**本調査で最も費用対効果が高い単一の打ち手。**
- **3-b. 棄却促進システムプロンプト**（コストゼロ）: AbstentionBench。
- **3-c. 十分性判定の外部化**（LLM +1回）: Sufficient Context の selective generation で **+2〜10%**。
- **やってはいけないこと**: 「よく考えてから答えて」型のCoT。小規模モデルでは **+1〜3ptしか効かない**。
- **必須**: Abstention Precision（over-abstention）を計測に追加。**166問全カテゴリ同時計測が前提。**

### 優先度4: 索引時の仮想質問生成 + 品質フィルタ（2〜4日 / 応答時間ゼロ / 効果 中〜高）

- gemma4:12b で各チャンクに想定質問を3〜5個生成し dense/BM25 両方に付与。
- **フィルタ必須**（Doc2Query--: フィルタで最大16%改善、索引33%削減）。
- **完全オフライン・追加embedモデル不要・応答時間ゼロという当製品の制約に唯一完全に適合する高効果手法。**
- 代償: インデックス増（最大5倍）、初回索引時間増。
- **日本語・防衛白書での実証は存在しない。当製品で測るしかない。**

### 優先度5: Step-back または Query2doc（1日 / +2〜5秒 / 効果 不確実）

- C5のみ対象。**LLM呼び出し1回で済む最も安価なクエリ側手法。**
- Step-back は **12Bでの実証なし**、新規エラー5〜12%のリスク。
- Query2doc は BM25 +3〜15%、**HyDEより安全**。
- **C5は166問中17問（10%）。この17問のために全質問に+3秒乗せる設計は避ける**が、ルールベースのルーティングには **-1.8 EM の悪化実測**があるのでルーティング自体もA/B必須。

### 優先度6: Chain-of-Note のプロンプト版（1〜2日 / 効果 不確実）

- ノイズ文書下 EM +7.9、棄却率 +10.5（**7Bにfine-tune**）。**プロンプトのみで12Bが同等に動くかは不明。**

### 採用しない（明確な負の実証あり）

- **Self-RAG** / **FLARE**: 7B/13Bで単純RAGより悪い。
