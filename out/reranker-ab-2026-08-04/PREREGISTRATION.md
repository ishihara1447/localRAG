# 事前登録票: リランカー新旧 A/B（防衛白書30問）

- **作成時刻: 2026-08-04T13:01:14+09:00（JST）**
- **本票は測定開始前に確定させたものであり、結果を見た後に一切変更しない。**
- 変更が必要になった場合は、変更せず「逸脱」として別途記録する。

## 0. 答えを出したい問い

新リランカー `hotchpotch/japanese-reranker-xsmall-v2` は、旧 `onnx-community/bge-reranker-v2-m3-ONNX`
と比べて防衛白書30問の精度が落ちるか。落ちるならどれだけか。

## 1. 条件

| 記号 | `RERANKER_MODEL_PREF` | 呼称 |
|---|---|---|
| **A** | `onnx-community/bge-reranker-v2-m3-ONNX` | 旧（BAAI・中国系・570MB） |
| **B** | `hotchpotch/japanese-reranker-xsmall-v2` | 新（日本発・37MB） |

**`RERANKER_MODEL_PREF` 以外は一切変えない。** 同一ホスト・同一 image
（`localrag-anythingllm:1.0.7`）・同一ワークスペース（`ttft-hakusho`, topN=8,
temperature=0, similarityThreshold=0.25, openAiHistory=20）・同一コーパス
（`R07zenpen.pdf` 1件、再取込みしない）・同一システムプロンプト（928字、変更しない）・
同一 LLM（`gemma4:12b` / Ollama / think OFF）・同一埋め込み（`bge-m3:latest`）。
`LANCE_HYBRID_SEARCH=true` / `LANCE_HYBRID_RERANK=true` / `LANCE_SENTENCE_CUSHION=true` /
`QUERY_REFORMULATION=true` は両条件で共通のまま。

## 2. run 数と実行順（交互）

- 各条件 **3run**、合計 **6run**。
- 実行順は **A1 → B1 → A2 → B2 → A3 → B3**（交互）。時間経過による drift を相殺する。
- 各 run の直前に **必ずコンテナを再作成する**（モデルは静的シングルトンで起動時に1回だけ
  ロードされるため、切替には再作成が必須）。結果として **両条件とも「コンテナ再作成直後の
  コールドスタート」で揃う**。片方だけウォームという不公平は生じない。
- 各 run に一意な `HAKUSHO_RUN`（= 設問ごとの `sessionId` に埋め込まれる）を与える。
  値は `A1 A2 A3 B1 B2 B3`。**`sessionId` を振らないとチャット履歴が交絡する**
  （`docs/EVAL_HARNESS_FIXES_2026-07-26.md` の実証済み事故）。`scripts/hakusho-eval.py` は対応済み。
- 評価スクリプトは `scripts/hakusho-eval.py` を**無改変**で使う。
  環境変数は `HAKUSHO_SLUG=ttft-hakusho`, `HAKUSHO_RUN=<run>`, `HAKUSHO_OUT=<JSON>` のみ。
  **`TOPN` / `CHAT_MODEL` / `PROMPT_FILE` は指定しない**（指定するとワークスペースを
  書き換えるため。スクリプトは復元しない既知の問題がある）。

## 3. 指標

- **主要指標**: 30問の合計正答数（0〜30）。条件ごとに 3run の**平均**を取る。
  Δ = mean(B) − mean(A)。単位は「点」（＝問）。
- **副次指標（カテゴリ別、必ず見る）**:
  - a) 直接事実 8問 / b) 数値判別 6問 / **c) 定義説明 6問** / **d) 白書外・不明応答 5問** / e) 言い換え 5問
  - **c) 定義説明** はリランカーを外すと 6/6 → 2/6 に壊滅する、リランカーの効きが最も出るカテゴリ。
  - **d) 白書外** はハルシネーションの有無。
- **参考指標**: リランクの所要時間（コンテナログの `Reranking N documents to top N took Xms`）、
  1問あたりの応答秒（実行ログ JSON の `sec`）。**採否の判定には使わない**（精度の問いに答えるため）。

## 4. 合否基準（事前確定・以後変更しない）

順に判定する。

| # | ゲート | 内容 | 違反時 |
|---|---|---|---|
| **G1** | ハルシネーション | B の **d) 白書外が 3run すべてで 5/5** であること | **採用不可**（無条件） |
| **G2** | 定義説明 | **mean(B の c) ≥ mean(A の c) − 0.67**（＝3run 中1run で1問落ちる程度までは許容） | **採用不可** |
| **G3** | 総合 | Δ = mean(B) − mean(A) | Δ ≥ **−1.0** → **採用可**<br>−2.0 ≤ Δ < −1.0 → **条件付き（保留・追加測定を要求）**<br>Δ < **−2.0** → **採用不可** |

**G3 の閾値を −1.0 に置いた理由（事前に明記する）**: ユーザーから
「非中国系のリランカーを必ず適用してほしい。**回答速度と精度が多少落ちることは許容する**」
という指示が出ている（`docs/RERANKER_SWAP_2026-08-04.md` §2）。したがって
「同等以上でなければ不可」ではなく「多少の低下は許容、大きな低下は不可」が要件に合う。
30問中1問（3.3pt）を「多少」、2問超（6.7pt超）を「大きな低下」と定義した。
**この閾値は結果を見る前に決めたものであり、結果に合わせて動かさない。**

## 5. 集計規則（事前確定）

1. **6run すべてを報告する。** 事後に「調子が悪かった」等の理由で run を除外しない。
2. run を破棄してよいのは、下記「無効化条件」に該当したときのみ。破棄した場合は
   **同じ条件で採り直し**、破棄した事実と理由を報告書に必ず残す。
3. 平均は小数第2位まで。四捨五入。
4. カテゴリ別も 3run 平均で示すが、**run ごとの生値も必ず併記する**。
5. 生データ（実行ログ JSON・コンテナログ抜粋）は `out/reranker-ab-2026-08-04/` に保存する。

### 無効化条件（run を破棄して採り直す）

- **(V1)** run 中またはその前後の `ollama ps` で `gemma4:12b` の `PROCESSOR` が
  `100% GPU` でない（CPU 転落・部分オフロード）。
- **(V2)** コンテナログでその run が期待したモデルを読んでいることを確認できない
  （`Loaded model <期待値>` および `[BundledAssets] 同梱リランカーを確認しました: <期待値>` が出ない）。
- **(V3)** run 中にリランカーの例外・フォールバックを示すログが出た
  （`Failed to load` 等）。**リランカーは失敗時に静かに元順序へフォールバックする設計**なので、
  ログでの確認を必須とする。
- **(V4)** HTTP エラー等でスクリプトが 30問を完走しなかった。

## 6. 副次解析（探索的・判定には使わない）

- 30問それぞれについて 3run の**多数決**（2/3以上正答なら正答）で条件ごとに二値化し、
  対応のある 30 ペアを作る。不一致ペア数から **McNemar 検定（二項の正確検定、両側）** の
  p 値を出す。
- **この p 値は採否の判定に使わない。** n=30 は検出力が低く、
  **「p が有意でない」を「差が無い」とは書かない**。
- カテゴリ別の差も、6問・5問という規模では 1問の増減が 16〜20pt に相当するため、
  **方向性の観察にとどめ、断定しない**。

## 7. 事前予測（外れたら「外れた」と書く）

測定前の予測を記録する。

| 項目 | 予測 |
|---|---|
| Δ = mean(B) − mean(A) | **−1.0 〜 +0.5 の範囲に入る**（点推定は **−0.5**） |
| G1（B の d が全 run 5/5） | **満たす** |
| G2（c 定義説明） | **満たす**。両条件とも 5〜6/6 で並ぶ |

現行ベースライン 28/30 は**別ワークスペース・`LANCE_HYBRID_RERANK` 導入前**の測定であり
A の実測値がそこに一致する保証はないこと。

## 8. 想定される交絡と、その扱い

- **現行ベースライン 28/30 との非可比性**: 28/30 は 2026-07-26 に別ワークスペースで、
  かつ `LANCE_HYBRID_RERANK=true` の確定（2026-07-27）より**前**に測られている。
  本 A/B では **A（旧モデル）を今この構成で測り直す**ので、
  **判定は本 A/B 内の A と B の比較のみで行う**。28/30 は参考としてのみ言及する。
- **コンテナ再作成に伴う状態差**: 両条件とも毎 run 再作成するので条件間で対称。
- **LanceDB のインデックス**: 再取込みを一切行わないので両条件で同一。
